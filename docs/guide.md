# Ripple 사용 가이드

Ripple을 처음 쓰는 팀원·현직자 인터뷰 진행자·심사 위원을 위한 화면 사용법입니다. 단추·탭 이름은 실제 화면 문구 그대로 적었습니다.
라이브 주소는 [ripple-ecn.up.railway.app](https://ripple-ecn.up.railway.app)이고, 지금 데이터는 **가상 수에즈막스 원유운반선의 합성 데이터**입니다(실제 회사·호선 자료가 아닙니다).

## 1. 들어가기

- 주소로 들어가면 소개 화면이 나오고, **로그인**을 누르면 로그인 화면으로 갑니다.
- 가입은 없습니다. 관리자가 사용자 메뉴의 **구성원 관리**에서 계정을 만든 뒤 임시 비밀번호를 직접 전해 줍니다(임시 비밀번호는 만든 창에서 한 번만 보입니다).
- 첫 로그인과 비밀번호 초기화 뒤에는 새 비밀번호를 정합니다. 10~128자이고, 아이디 그대로이거나 아이디에 3자 이하만 덧붙인 비밀번호, 같은 글자만 반복한 비밀번호, 흔한 비밀번호는 쓸 수 없습니다.
- 로그인은 12시간 유지됩니다. 같은 아이디로 15분 안에 5번 틀리면 잠시 로그인이 막힙니다.
- 역할은 네 가지입니다(라이브에서는 체험 계정을 껐습니다).

  | 역⁠할 | 할 수 있는 일 |
  |---|---|
  | 팀⁠장 | 결재자: **결재·현황**(결재함·현황·성과·관리), 결재선 2단계 승인·반려·보류와 파트장·본부장 단계 전결, 분석 보기, 지도 전환·엑셀 가져오기, 구성원 관리, 감사 로그 확인 |
  | 파⁠트⁠장 · 본⁠부⁠장 | 결재자: **결재·현황**(결재함·현황·성과), 결재선 1단계(파트장)·3단계(본부장·실장)의 승인·반려·보류, 분석 보기, 감사 로그 확인 |
  | 담⁠당⁠자 | 분석·대안·AI 비서, 기록·검토 요청·실행 시작·종료, 결재 상태·이력 보기, 지도 엑셀 내려받기, 발주·공정 상태 확인·상태 올리기 |

## 2. 화면 한눈에

- **위 막대**: 지금 쓰는 지도(합성 데이터·실제 데이터 표시), **찾기**(Ctrl+K 명령 팔레트), 밝게·어둡게, 사용자 메뉴(**비밀번호 바꾸기…** · **구성원 관리**(관리자) · **감사 로그 확인**(관리자) · **로그아웃**).
- **왼쪽 목록**: 설계변경을 결정 기한이 급한 것부터 → 판정 → 비용 순으로 보여 줍니다. 판정으로 거를 수 있고 J/K로 움직여 Enter로 엽니다.
  - 거르기 칸에 결재자는 **결재 대기**, 담당자는 **내 건**(내가 올린 설계변경 — 반려·보류는 사유 한 줄)이 있습니다. 한 건은 목록에 한 번만 나옵니다.
  - 지금 지도 목록에 없는 기록은 아래 **기록된 다른 설계변경**에 있습니다.
- **가운데 상세**: 판정과 이유, 핵심 수치, **영향 지도**, **할 일**, 탭(**비용 · 일정 · 추가손실 곡선 · 대안 · 이력**).
- **오른쪽 AI 비서**: 설계변경을 문장으로 적으면 대상을 찾아 분석하고 설명·알림 초안을 만듭니다. 넓은 화면(1440px 이상)에서는 처음에 닫혀 있고, 위 막대 **AI 비서** 단추로 열고 닫습니다(연 상태는 브라우저에 기억).

## 3. 설계변경 하나 판단하기

1. 목록에서 설계변경을 엽니다.
2. **판정**(승인 가능 · 검토 필요 · 경고)과 이유 한 줄을 봅니다.
3. **총변경비용**(대표값과 범위)과 **결정 기한**(D-n — 이날까지 확정하면 추가손실 0)을 봅니다.
   - 결정 기한 카드의 **확정일을 ○월 ○일로**를 누르면 그날 확정하는 것으로 다시 계산합니다(확정일이 결정 기한을 넘었으면 **결정 기한으로 당기기**). 카드 안 작은 곡선(하루 늦으면 늘어나는 금액)을 누르면 추가손실 곡선 탭이 열립니다.
   - 판정·핵심 수치·기준일·확정일·적용 시작일·설계 승인 옆의 **ⓘ**를 누르면 용어 설명이 나옵니다.
4. **영향 지도**: 바뀐 부재에서 블록·발주·도면·공정으로 이어지는 영향 그래프입니다(좁은 화면은 들여쓴 목록).
   - 카드를 누르면 바로 아래에 규칙과 근거 경로가 보입니다.
   - 그 아래 **연결 추적**을 펼치면 바뀌는 부재마다 도면 → 블록 → 발주 품목 → 소비 공정으로 이어지는 연결이 한 줄씩 나오고, 지도에서 끊긴 연결은 확인 필요로 표시됩니다.
5. **할 일**: 두 묶음입니다.
   - **조치**: 발주 보류 권고·의장품 선상 설치처럼 지금 할 일입니다. **보류 적용**·**선상 설치로 계산**을 누르면 그 가정으로 다시 계산해 위에 **바뀐 점**(판정·비용·지연)을 보여 주고, 영향 지도도 새 결과로 바뀝니다(실제 발주·생산 계획에는 반영되지 않습니다). 이 화면으로 기록하면 가정이 개정에 함께 남습니다.
   - **계산에 쓴 현장 상태**: 이 판단을 만든 발주·공정의 상태입니다. 발주 단계는 구매, 공정 실적은 생산관리가 아는 정보라 처음에는 '구매 1 · 생산관리 3'처럼 확인할 부서만 한 줄로 보이고, 펼치면 확인이 필요한 것부터 나옵니다(근거 없음 → 계획으로 추정 → 7일 넘게 확인 안 함).
     - 지금 보이는 상태가 맞으면 **맞아요**, 다르면 **고칠게요**(발주 단계·입고까지 일수, 공정 실제 착수·완료일)로 남깁니다.
     - 오늘 날짜로 지도에 남고(누가·언제 기록) 같은 조건으로 바로 다시 계산합니다. 기준일이 오늘이 아니면 확인할 수 없습니다.
6. 탭으로 근거를 봅니다.
   - **비용**: 맨 위 **발주 조치**가 이미 발주한 품목을 단계별로 무엇을 할지(변경·취소·재발주·재고 전용·보류) 묶어 보여 줍니다(`docs/engine.md`(비용·일정) 4-10). 항목을 펼치면 왜 생기는지, 계산, 가정과 범위(근거 상태), 확정이 늦어지면 언제 얼마로 바뀌는지가 나옵니다.
   - **일정**: 블록 공정별로 늘어난 일수, 구역 출구·인도 예상 지연. 공정 선후행·자재 리드타임만으로 계산한 추정이라 인력·정반·크레인 같은 자원 제약과 납기 변동은 반영하지 않습니다(화면 맨 아래에 같은 안내).
   - **추가손실 곡선**: 확정일을 60일 뒤까지 밀어 본 금액입니다.
   - **대안**: 판 두께·강종·보강재 같은 강도형 요청이면 대안과 예비 강도 비교, 최저 비용 조합(대안·확정일·보류), 확정을 미룰 때 날짜별로 최저 비용 대안이 나옵니다. 대안 줄의 **이 대안으로 분석 보기**로 그 대안을 상세에 엽니다.
   - **이력**: 기록·검토·결정 줄(누가·언제·무엇을·사유)입니다.
7. 상세 위의 **확정일**을 바꾸면 그날 확정한다고 보고 바로 다시 계산합니다.
8. 같은 줄의 **설계 승인**(미입력 · 설계 검토 중 · 선주 승인 대기 · 승인)과 **적용 시작일**을 넣을 수 있습니다.
   - 승인 전이면 판정에 "설계 승인 전 변경 · 승인 상태 확인 필요"가 붙습니다.
   - 적용 시작일은 기록·검토서에만 남고 계산에는 쓰지 않습니다(확정일보다 빠르면 메모가 붙습니다).
   - 둘 다 바꾸면 기록할 때 새 개정으로 남습니다.

## 4. AI 비서로 새 설계변경 분석하기

- 예: "선주 요청으로 펌프룸 스트리핑 글로브 밸브 1번을 볼 밸브로 바꿔 주세요"
- 대상이 확실하지 않으면 후보를 보여 주고 고르게 합니다. **금액·일정·판정은 AI가 아니라 엔진 규칙이 계산**하고, AI는 문장 해석과 설명 문장 고르기만 돕습니다.
- 변경 사유는 분석이 끝난 뒤 묻습니다.
- 알림 초안(협력사·재작업 블록 담당·도면 담당)은 공식 메일 형식입니다.
  - 카드의 **Gmail로 쓰기**로 새 탭의 Gmail 쓰기 창에 채워 열고, **메일 보내기…** 창에서 여러 통을 한 통씩 차례로 엽니다.
  - 보내기는 Gmail에서 직접 누릅니다(실제 데이터 지도에서는 복사만 됩니다).
  - 본문이 길면 클립보드에 복사되니 붙여 넣은 뒤 **붙여 넣었어요**를 누릅니다.
  - 합성 지도의 받는 사람은 시연용 가상 연락처(.example)라 실제로 배달되지 않습니다(`docs/records.md`(통보)).
- 올린 엑셀로 만든 지도(실제 데이터)에서는 외부 AI를 부르지 않고 서버 규칙만으로 해석하고 설명합니다.

## 5. 기록하고 결재받기

상세 머리 아래 **결재 띠**에 상태·개정·기록한 사람과 지금 할 수 있는 행동이 나옵니다. 할 수 없는 행동은 흐린 단추와 이유 한 줄로 보입니다.

1. 담당자: **검토 요청…**을 누르면 확인 창에 올릴 내용(판정·총변경비용·결정 기한)이 나오고, 확인하면 지금 화면의 분석을 바뀌지 않는 개정으로 **기록한 뒤 바로 검토를 요청**합니다(이미 기록된 분석이면 요청만).
   - 결재 없이 이력만 남길 때는 **기록만 남기기**를 씁니다.
   - 검토 중에는 **검토 취소**를 할 수 있습니다.
   - 반려·승인 뒤 고친 분석도 같은 **검토 요청…**으로 다시 올립니다.
2. 결재자(결재선 파트장 → 팀장 → 본부장 차례): 로그인하면 **결재·현황**의 **결재함**(자기 결재 단계)이 먼저 뜹니다. 결정 기한이 급한 것부터 줄마다 결정 기한(D-n), **미루면**(결정 기한 다음 날 확정하면 늘어나는 금액)이 보입니다. **엑셀로 내보내기**로 결재 대장(결재함 줄·현황)을 엑셀로 받습니다. **열기**를 누르면 업무 화면에서 그 개정의 기록된 분석이 열리고, 결재 띠에서 결정합니다(업무 화면 목록의 **결재 대기** 칸에서 열어도 같습니다). 결재 중인 건의 분석 조건(확정일·변경 원인 등)은 기록한 담당자만 바꿀 수 있습니다.
   - **승인**: 확인이 필요한 항목(계산 불가 항목, 가져온 지도의 경고)을 하나씩 체크하고 사유를 적습니다.
   - **반려**·**보류**: 사유를 적습니다.
   - 화면의 분석이 기록한 개정과 다르면 **기록된 분석 열기**로 기록한 조건 그대로 다시 엽니다.
   - **현황**: 결재 대기·결정 기한 임박, 아직 결정 안 된 금액, 상태별·블록별.
   - **성과**: 기간별 결정 수·반려율·처리 시간, 결정 기한 안 결재 비율과 그로써 피한 추가손실, 담당자별 업무량(업무 분배용).
   - **인쇄·PDF**로 현황·성과를 한 문서로 뽑습니다.
3. 승인 뒤 담당자가 **실행 시작** → **종료**. 승인한 뒤 지도가 바뀌어도 실행은 할 수 있고, 기록에 그 사실이 남습니다.
   - 실행한 뒤에는 결재 띠 아래 **실적 입력…**으로 실제 든 변경 비용(만원)과 구역 출구 지연을 넣습니다.
   - 관리자의 **성과** 탭 **예측 대비 실적**에 승인한 예측과의 오차가 쌓여, 비용 가정이 맞는지 확인하는 근거가 됩니다.
4. 다른 사람의 결재는 창을 다시 보거나 20초 안에 화면에 반영됩니다.
5. 모든 단계는 고칠 수 없는 감사 로그로 남습니다(**이력** 탭). 관리자는 사용자 메뉴의 **감사 로그 확인**으로 기록이 바뀌지 않았는지 확인합니다.

## 6. 설계변경 검토서(A4 인쇄·PDF)

- 결재 띠의 **검토서 인쇄**나 이력 탭·결재함의 **검토서**를 누르면 새 탭에 A4 세로 설계변경 검토서가 열립니다.
  - 본문: 문서 머리(ECN 번호·호선·대상 블록·작성일·작성자) → 변경 내용·사유 → 판정과 핵심 수치 → 영향 범위 요약 → 비용 내역 → 일정 → 중량 변화 → 조치 사항 → 결재란(담당·파트장·팀장·본부장).
  - 붙임: 확정을 미루면 · 대안 · 연결 추적 · 결재 이력.
- 위 **검토서 인쇄** → 브라우저 인쇄 창에서 'PDF로 저장'을 고릅니다. 어둡게 쓰고 있어도 검토서는 밝게(흰 종이) 인쇄됩니다.
- 검토서의 숫자는 **기록할 때의 분석 그대로**입니다(지금 다시 계산한 값이 아닙니다). **업무 화면으로**를 누르면 돌아갑니다.

## 7. 엑셀 가져오기(관리자)

1. 위 막대의 지도 단추 → **엑셀 가져오기**. 양식은 가져오기 창의 **양식 예시 내려받기**나 지도 메뉴의 **이 지도 엑셀로 내려받기**로 받습니다(작성 규칙은 [`docs/input.md`(엑셀 양식)](input.md#엑셀-양식)).
2. 파일을 올리면 열 확인 단계가 나옵니다. 확실한 열은 자동으로 맞추고, 애매한 열과 머리글 밖에만 적힌 단위는 직접 고르게 합니다 → **이대로 읽기**.
3. 품질 리포트(시트·행·열, 빠진 연결)를 보고 **이 지도로 전환**을 누릅니다.
4. 올린 엑셀은 실제 데이터로 다뤄 외부 AI 호출이 0입니다. 분석 기준(호선·기준일, 기본은 파일 안 마지막 상태 날짜)은 목록 칸에서 바꿀 수 있고, 새 설계변경은 AI 비서에 적어 분석합니다.
5. 처음 지도로 돌아가려면 지도 메뉴에서 **기본 합성 지도**를 고릅니다.
6. 같은 모양의 엑셀을 다시 올리면 지난번 열 확인을 그대로 써서 바로 품질 리포트로 갑니다(제목 행의 단위가 바뀌는 등 모양이 다르면 다시 확인합니다).

## 7-1. 매일 바뀌는 상태 올리기(담당자 이상)

1. 지도 메뉴 → **상태 올리기(발주·공정)**. ERP에서 매일 뽑는 발주 현황·공정 실적 엑셀을 그대로 올립니다.
2. 발주·발주 관측·공정·공정 확인 시트만 읽습니다(빈 칸은 바꾸지 않음). 다른 열·시트는 읽지 않습니다.
3. 미리보기에서 **바뀌는 것**(단계 변화·납기 전후·공정 실적)과 **맞지 않는 항목**을 봅니다. 하나라도 맞지 않으면 반영하지 않습니다.
4. **이 내용으로 갱신**을 누르면 지금 지도에 덮어쓰고 목록·분석을 다시 계산합니다. 부재·블록·공정 구조는 바뀌지 않습니다.
5. 지도 메뉴의 **자료 날짜**에 발주 상태·공정 실적이 언제 기준인지와 7일 이상 미확인 발주 수가 나옵니다(있으면 지도 단추에 점). 합성 시연 지도는 매일 한국 시간 오늘로 다시 만들어 기준일도 오늘입니다(자정이 지나면 새 날의 지도로 바뀌어, 전날 기록은 '다른 지도'로 보입니다).

## 8. 알아 둘 것

- 비용 가정값(재작업 공수·도면 개정 공수·인건비 단가 등)은 공개 자료와 가정의 범위이고, 현업 확인 뒤 바꿀 예정입니다. 화면의 '가정과 범위'에 근거 상태가 함께 보입니다.
- 일정은 대표 리드타임으로 계산합니다. 새 규격 강재를 다시 발주하는 두께·강종 변경은 리드타임이 길어지면 구역 출구가 늦어질 수 있어 '자재가 늦게 오면'으로 따로 보입니다.
- 새 버전이 배포된 직후 화면이 이상하면 새로 고침(Ctrl+F5)합니다. 재배포 때 약 1분 멈추므로 발표·시연 중에는 배포하지 않습니다.
