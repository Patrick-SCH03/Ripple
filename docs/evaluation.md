# 평가 기준과 측정 기록

합격 기준(E1~E9)과 단계 관문, 개발 분할에서 잰 값을 적는다. 기준은 평가셋과 숨긴 실제 비용 모델을 만들기 **전에** 고정했다.
지표별 사례 대조는 [평가 보고서](eval_summary.md), 데이터 구성과 한계는 [데이터 카드](data.md#데이터-카드), 판단 계층 기준(E8)은
[판단 계층](input.md#판단-계층) 5절, 엑셀 열 매핑 인증(E6)은 [`eval/columns/v1_eval.md`](../eval/columns/v1_eval.md).

## 1. 합격 기준

| ID | 지표 | 방법 | 비교 기준 | 합격 기준 |
|---|---|---|---|---|
| E1 | 영향 탐색 정밀도·재현율 | 손 계산 경계 사례 30건(의미 정확도) + 평가 100건(잡음 강건성) | where-used 추적 | 30건 재현율 ≥ 0.95·정밀도 ≥ 0.9, 100건 F1이 기준선보다 높음 |
| E2a | 비용 정확도(기본 엔진) | 숨긴 실제 비용 대비. 실제 100만원 이상 사례는 절대 백분율 오차, 미만 사례는 절대 오차(원) | — | 100만원 이상: 오차 중앙값 ≤ 25%·90백분위 ≤ 60%, 미만: 오차 50만원 이내 ≥ 90% |
| E2b | 실적 보정 개선 | 보정 전후 평균 절대 오차(원) | 실적 보정 전 | 보정 후 < 보정 전. 실적 보정을 하지 않으면 '해당 없음'(E2a는 그대로 적용) |
| E2' | 일정 정확도 | 일 단위 절대 오차 + 지연 발생 여부의 오경보율·누락률 | — | 평균 절대 오차 ≤ 2일, 오차 7일 이상 사례 ≤ 5%, 오경보율·누락률 각 ≤ 10% |
| E3 | 자연어 해석 정확도 | 현장 용어·약어·오타 섞인 문장, 변경 연산·대상·값 정확도 | 규칙 기반 해석기 | ≥ 0.9 |
| E4 | 설명문 수치 | 설명·알림의 수치가 모두 수치 블록(필드별 고정 라벨·틀)에서 나왔고 글 블록에 숫자가 없는가 | — | 100% |
| E5 | 건당 분석 시간 | 입력부터 결과까지 | 수작업 엑셀 추적 | 엔진 ≤ 1초, LLM 포함 ≤ 10초 |
| E6 | 엑셀 매핑·연결 정확도 | 지저분한 변형 여러 종 | 동의어 사전만 | 열 매핑 ≥ 0.95 |
| E7 | 결정 일치 | 엔진이 고른 (대안·확정 시점·보류) 조합을 숨긴 실제 비용 기준 최선과 비교 | — | 같은 조합 비율 ≥ 0.8, 평균 후회 비용 ≤ 실제 최선 비용의 5% |
| E8 | 판단 계층 보정 | 후보 재현율·대상 특정 정확도·되묻지 않은 건 정확도·되묻지 않은 비율·예측 집합 포함률·ECE·지연 | — | `docs/input.md`(판단 계층) 5절의 기준 모두 충족 |
| E9 | 문서 접수 확인표(1.27.0, `docs/input.md`(문서 접수)) | 합성 문서(생성기 문장 2~5개 × ECN 양식·메일·변경 리스트 표 × 적대 변형)의 확인표를 사람 눈 기준으로 채점 | 규칙 경로 | 사람에게 보이지 않은 정답 0건 · 문제 표시 재현율(지금 값 다름·개정 다름) ≥ 0.95 · 지원 안 함이 경고 없이 8종으로 0건 · AI 경로 항목 재현율(연산·대상·값까지 정확) ≥ 0.9 |

해석 규칙(측정 도구를 만들며 평가 분할을 열기 전에 정했다).

- **E2a** 구간은 실제 총액의 **절댓값**으로 나눈다. 비용이 줄어드는(음수) 사례도 크기가 100만원 이상이면 백분율 오차로 본다.
  개발 분할에서는 두 해석 모두 합격이다(절댓값 141/59건 9.6%·98.3%, 부호대로 137/63건 9.6%·95.2%).
- **E2'** 는 구역 출구 최대 지연과 늘어난 인도 지연(엔진·숨긴 모델 모두 계산된 사례) 두 값에 모두 기준을 적용한다.
  - 오경보율 = 실제로 지연이 없는 사례 중 엔진이 지연을 낸 비율, 누락률 = 실제로 지연이 생긴 사례 중 엔진이 0일이라 한 비율.
  - 조건은 E2a와 같다(확정일 = 기준일, 보류 없음).
- **E7** 은 엔진 최적 조합과 같은 후보 공간·고르기 순서(`docs/engine.md`(대안) 4절)로 숨긴 모델 기준 최선을 찾는다.
  - 같은 조합 = 대안·확정일·보류 행동이 모두 같음. 확정 가능일 기준일·+10일·+20일 세 조건 모두 합격해야 합격이다.
  - 후회 기준의 분모는 실제 최선 총액 **절댓값의 평균**이다(총액이 음수일 수 있어서). 분모를 '평균의 절댓값'으로 바꿔도 개발
    분할은 0.81% · 0.57% · 0.31%, 시드 1~5 최대 1.02%로 합격 그대로다(음수 최선 사례는 조건마다 4~14건).
- 개발 200건과 평가 100건은 생성 단계에서 나누고 평가셋으로 튜닝하지 않는다. 평가 100건은 정답이 생성기의 연결 구조에서 나와
  엔진과 같은 의미 체계이므로 잡음 강건성과 기준선 대비 차이에만 쓰고, 의미 정확도는 손 계산 30건으로 잰다.
- 숨긴 모델은 파라미터 범위 안에서 고정 시드로 뽑은 값과 사례별 잡음을 쓰고 엔진 대표값으로 맞추지 않지만(`docs/data.md`(생성기)),
  엔진과 같은 명세·범위를 공유하므로 E2a·E2'·E7은 **현장 정확도를 입증하지 않는다**.

## 2. 단계 관문

| 단계 | 관문 |
|---|---|
| 1 지도 + 영향 탐색 | 손 계산 영향 사례 10건 재현율 100%·정밀도 ≥ 0.9, 변경 입력 → 영향 범위와 근거 경로가 화면에 뜸, 판단 계층 성질 검사(포함률·오류율 보장) |
| 2 계산기 + 확정 시점 + AI 비서 | 손 계산 비용·일정 사례 10건 일치(금액 ±1%, 일정 ±0일), 자연어 입력부터 알림 초안까지, 설명문 수치는 모두 수치 블록, 판단 계층 보정 산출물과 선택 분할 E8 사전 점검 |
| 3 대안 + 엑셀 + 결재 | 손 계산 대안 판정 5건 일치, 엑셀 변형 3종 정답 매핑 일치, 엑셀 업로드 → 지도 생성 → 분석이 한 번에 이어짐 |
| 4 평가·배포 | 1절 기준 충족(평가 분할 최종 인증 1회) |

관문 정답 사례는 엔진 코드를 보지 않는 계산자가 별도 폴더에서 계산하고 사람이 검토한다(양식과 절차는 `docs/gate_cases.md`).

## 3. 측정 기록(개발 분할, 합성 지도 기본 시드 20261020)

평가 분할의 E2a·E2'·E7 정답·점수는 아직 열지 않았다(최종 인증 때 한 번). 시드는 합성 세계 전체를 다시 만든 반복이다.

### E1 — 손 계산 30건

- 사례: 관문 10건 + 경계 사례 20건(`ripple/eval/gate_inputs.py` `_boundary_cases`) — 두께 차 문턱(얇은 쪽 10mm 이하·초과), 판정일
  발주 단계(발주 전날·당일)·블록 소조립(전날·당일), 잉여 자재 두 방향, 연결 규격 같음, 관통·칼라, 한 판 두 연산, 새 부재 연결,
  단계 모름, 가공 끝난 품목 등. 대상은 조건으로 고르고 기대값은 만들지 않았다.
- 채점(`scripts/gate_cases.py score`): 30건 모두 일치 — 판정 단위 **재현율 1.000 · 정밀도 1.000**(기대 영향 136건), 계산하지
  못한 이유도 같음.
- 기준선(엔터티 단위 F1, `ripple/eval/impact_metrics.py`):
  - **PLM 수준 조회(블록·공급 품목·도면)** 를 기준선으로 잡는다: **0.657 → 엔진 1.000**.
  - 도면을 보지 않는 where-used(부재 → 블록·공급 품목)는 **0.439**로 불리하게 짜여(정답 136건 중 도면 개정 36건) 기준선으로 쓰지 않는다.
  - 차별점은 그 기준선 밖의 정답 엔터티(2차 영향) **51개 중 51개**를 찾는 것 — 용접 재검토 18·이웃 도면 개정 8·테이퍼 8·배관
    부재 수정 6·이웃 블록 재작업 5·관통 칼라 5·잉여 재고 전용 3 등.
- 연결 자료 제거(`scripts/eval_connections.py` → `eval/reports/connections_ablation.json`):
  - 같은 30건을 부재 사이 연결 741개(맞대기 용접 290·필릿 용접 388·배관 이음 45·지지 14·관통 4)를 뺀 지도에서 다시 채점하면
    재현율 **0.772**(136건 중 105), 2차 영향 **51개 중 20개**, 관문 미달.
  - 사라지는 것은 용접 재검토 18→0·테이퍼 8→0·배관 부재 수정 6→3·관통 칼라 5→4·이웃 도면 개정 36→35이고, 재작업 21·발주
    변경 22·재발주 16·잉여 재고 전용 3은 그대로다.
  - 정밀도 0.875는 대상 판마다 '연결 정보 없음 — 그 경로는 계산에서 제외'(R-X01, 15사례·16엔터티)를 낸 탓이고 그것을 빼면
    1.000이다.
  - 놓친 사례 11건 중 10건은 이 표시가 붙지만, R-X01은 판에만 걸려 배관 서포트 수정(G1-005, R-P03)은 **표시 없이 빠진다**.
    금지 영향 7건(G1-002·003·004·011·013·015·022의 대상 부재 R-X01 — 밸브 4·판 3).
  - 전체 제거만 쟀고, 이웃 하나만 빠진 일부 누락은 R-X01이 잡지 못한다(명세의 한계). 사례 30건은 규칙 경계를 고루 건드리게
    고른 것이라 실제 설계변경 분포의 평균이 아니다.
- 1절 E1의 '평가 100건 F1이 기준선보다 높음'(잡음 강건성)은 **아직 재지 않았다**(도구 없음).
- 한계: 사례 대상은 엔진 상태 함수로 골랐고 단일 지도라 독립 표본이 아니며, 사람 검토 전이라 잠정이다.
- 계산자와 검토:
  - 계산자는 엔진 코드를 보지 않은 AI 모델이고 **현직자 검토는 0건**(`checked_by` 모두 비어 있음)이다.
  - 엔진 채점 뒤 고친 정답(G2-008 마감일 다음 날 총액 최소 1건)은 사례 `notes`에 남는다.
  - 따라서 관문 값(1단계 1.000 · 2단계 13/13 · 3단계 5/5)은 **명세 적합성**(엔진이 명세를 그대로 따름)이고 현장 정확도가 아니다. 현직자 검토·서명 뒤
    `score --approved-only`로 다시 채점한다.
- **관문 지금 값**: 1단계 30건 1.000 · 2단계 **13/13** · 3단계 **5/5**. 48건 모두 지도 v3 기준으로 엔진을 보지 않는 계산자가
  다시 계산했고(근거 `eval/gate_cases/<단계>/worksheets/SUMMARY.md`), 지금 지도 v4는 지도 ID만 다시 찍었을 뿐 기대값은 같다
  (`gate_cases.py restamp`). CI가 세 단계 관문을 매번 채점한다.

### E2a — 비용 정확도

- 도구 `ripple/eval/cost_accuracy.py` · `scripts/eval_cost.py`: 엔진 대표 총액(대안 끔) vs 숨긴 모델(잡음 모드) 총액.
- 개발 200건(엔진 0.11.1 · cost-v7 · actuals-v4): 100만원 이상 147건 오차 중앙값 **9.0%** · 90백분위 27.4%, 나머지
  53건 50만원 이내 **98.1%** → 합격.
- 시드 1~5(실행 전에 고정): **2/5 합격**(엔진 0.11.1). 시드 3은 소액 87.5%, 시드 4는 중앙값 25.0%로 통과했지만 소액 80.0%,
  시드 5는 소액 89.3%.
  - 원인은 범위가 위로 넓은 파라미터가 많아 참값이 대표값보다 큰 쪽에 몰리는 것이다.
  - 엔진 범위 적중률은 96.0~99.5%이지만 범위 폭이 대표값의 171%라 넓은 범위 덕이 크다. 이 결과로 엔진·기준·숨긴 모델을 바꾸지 않는다.
- 해석 주의: 숨긴 모델의 참 파라미터는 엔진 범위 안에서 뽑고 대표값 둘레에 항목 잡음(로그정규)을 얹으므로, 오차 중앙값·90백분위는
  대부분 **넣은 잡음 크기를 다시 잰 것**이다(`ripple/generator/actuals/`). 발표에서 '비용 정확도'로 인용하지 않는다.

### E2' — 일정 정확도

- 도구 `ripple/eval/schedule_accuracy.py` · `scripts/eval_schedule.py`.
- 개발 200건(엔진 0.11.1 · cost-v7 · actuals-v4, 측정 전에 숨긴 모델 규칙을 정함 — 판 리드타임 변동은
  `docs/data.md`(생성기) 6-1): 구역 출구 최대 지연 평균 절대 오차 0.06일 · 7일 이상 0.5% · 오경보 0% → 충족, **누락 50%(실제
  지연 2건 중 1건) → 미달**. 시드 1~5 **2/5 합격**(누락 시드 3 7.7% · 시드 5 0% 충족, 시드 2 11.1% · 시드 1·4 100% 미달).
  인도 지연은 엔진·숨긴 모델 모두 0이라 판정력이 없다.
- 원인(요인 분리 `scripts/eval_factors.py`): 놓친 사례는 새 규격 강재를 다시 발주하는 변경이고, 원인은 **새 자재 리드타임
  하나**다.
- 대응: 고정 배율 하나로 기준을 다 맞출 수 없어(× 1.2면 누락 0%지만 7일 이상 오차가 일부 시드에서 기준 초과) 대표 일정은
  그대로 두고, 리드타임 범위 끝으로 계산한 지연을 '자재가 늦게 오면'으로 따로 보인다(`docs/engine.md`(비용·일정) 6-6).
- 위험 일정의 덮임:
  - 판(범위 끝 84일 = +14일)은 **실제 분포에 대한 덮임**이다: 실제 구역 출구 지연 ≤ 위험 199/200(시드 199~200/200), 실제 지연
    사례 중 위험이 0보다 큰 비율 개발 2/2 · 시드 38/38(엔진 0.11.1).
