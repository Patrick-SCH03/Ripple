# 데이터·근거 명세

Ripple 합성 데이터의 구성, 생성기, 파라미터·가정값의 공개 근거, 멘토에게 확인할 질문을 모은다. 편마다 절 번호를 따로 매기므로
코드 주석은 `docs/data.md`(생성기) 6-1처럼 편 이름과 절 번호로 가리킨다.

## 데이터 카드

개발·시연·평가에 쓰는 데이터는 **모두 합성 데이터**다. 실제 회사·호선·조선소 자료를 흉내 내지 않고, 값마다 근거 상태(근거
있음·가정·현업 확인)를 적은 설정과 시드로 만든다. 생성 규칙은 [`docs/data.md`(생성기)](#생성기).

### 2. 왜 합성인가

설계변경 영향 판단에 필요한 연결 자료(부재 ↔ 블록 ↔ 발주 품목 ↔ 공정 ↔ 도면)는 조선소 밖으로 공개되지 않는다. 그래서 공개
기사·문헌의 범위로 설정을 정하고, 실제 공정 단계(미착수 → 강재 입고 → 소조립 → 판넬조립 → 대조립 → 선행의장 → 선행도장 →
PE → 탑재)와
발주 단계(미발주 → 발주 → 자재 확보 → 제작 → 입고 → 가공)를 따르는 지도를 만든다. 실제 데이터로 쓰려면 엑셀 가져오기
(`docs/input.md`(엑셀 양식))로 회사 자료를 올리고, 그 지도는 실제 데이터로 다뤄 외부 AI 호출을 막는다.

### 4. 설계변경 300건과 분할

- **개발 200건**: 엔진·판단 계층을 만들고 사전 점검(E2a·E2'·E7 등)에 쓴다.
- **평가 100건**: 방법을 고정한 뒤 최종 인증 때 한 번만 연다(평가 도구는 `--final`이 있어야 돈다).
- 연산 분포(300건): 두께 77 · 치수 45 · 부재 추가 46 · 장비 사양 38 · 배관 경로 34 · 강종 27 · 부재 삭제 18 · 관통부 추가 15
  (설정의 가정 분포 25·15·15·15·10·10·5·5%에 맞춰 뽑음, 모두 연산 하나짜리).
- 데모 사례 3건(ECN-D-0119 · ECN-D-0045 · ECN-D-0130)은 개발 분할에서 골라 샘플 목록에 고정했다. ECN-D-0130(평형수 버터플라이 밸브 → 외자재 게이트 밸브 VL-GATE-DN200-10K)은 기본 요청의 일정 위험에 선박 운송 일수가 붙는 시연 건이다.

### 6. 평가 정답: 숨긴 실제 비용·지연 모델(`actuals-v5`)

- 엔진을 import하지 않는 별도 구현(`ripple/generator/actuals/`)이 엔진과 같은 명세를 다른 방식으로 계산한다. 규칙은
  `docs/data.md`(생성기) 6-1.
- 참 파라미터(`params/cost_v1.yaml` 범위 안 삼각분포, 최빈값 = 엔진 대표값)·항목 곱 잡음(σ 0.15)·엔진이 모르는 미반영 비용
  (사례마다 10% 확률, 양수 항목 합의 10~40%)·공정 착수 지연(0~3일)·새 규격 리드타임 변동은 엔진 결과를 보기 전에 정했다(결정 기록).
- 새 규격 리드타임 변동은 **판만 비공개 현업 강재 재고 집계의 실제 입고 지연 분포**(입고일 − 계약납기일, 중앙 +2일 · 90백분위
  +14일 · 범위 −45~+22일)이고 형강·배관·밸브·장비는 표준 × U(0.9, 1.2) 가정이다. 집계값만 쓰고 원자료는 저장소 밖에 둔다.
- 잡음·미반영 비용은 확정일·보류와 무관하다 — 같은 세계에서 결정만 바꿔 비교한다(E7).
- **한계**: 엔진과 명세·범위를 공유하므로 현장 실제 비용의 정확도를 입증하지 않는다. 다른 시드는 지도·일정·발주·설계변경·참
  파라미터까지 합성 세계 전체를 다시 만든다.
  - 시드 1~5에서 E2a는 2/5만 합격했다(엔진 0.11.1 — 시드 3·4·5가 소액 기준 미달 — 시드 3·4는 위로 넓은 파라미터 범위와 항목 잡음 탓으로 요인을 나눠 확인, 시드 5는 원인 미분리).
  - 일정은 새 규격 리드타임 변동(판은 실제 입고 지연 분포, 그 밖은 × 0.9~1.2)으로 생기는 작은 지연을 놓친다(E2' 누락 미달 —
    리드타임 배율 하나로 재현).
  - 요인 분리는 `scripts/eval_factors.py`, 자세한 값은 README '측정된 결과'와 `docs/evaluation.md` 3절.

### 7. 엑셀 변형

같은 지도를 Ripple 지정 양식(시트 16·열 100)으로 내보내고(`scripts/export_template.py`), 머리글 이름·두 줄 머리글·단위·날짜
표기·빈 행 등을 바꾼 흔한 변형을 정답 매핑과 함께 만든다(`scripts/export_variants.py`). 열 매핑 평가(E6)와 가져오기 검사가 쓴다.

### 8. 공개 실제 데이터와의 대조

합성 데이터 자체는 바꾸지 않고, 공개된 실제 데이터로 현실성과 엔진 동작을 확인했다. 데이터는 저장소 밖
data 폴더에 두고 출처(CC BY 4.0)를 밝힌다.

| 데이터 | 내용 | 확인한 것 |
|---|---|---|
| 선박 블록 일정(Mendeley 2bmbmbf8hm, 상하이교통대 2026, "실제 조선소 생산 데이터를 익명화를 위해 조금 고침") | 호선 2척 블록 872개(평 739·곡 133), 블록 중량 50~240t(중앙 152t), 정반 점유 기간 8~72(중앙 25, 10~90% 16~39, 단위는 일로 추정) | 합성 조립 공정 기간(12~18일 + 100t당 2~3일, 150t 블록이면 15~22.5일)은 실제 정반 점유 범위 안, 중앙보다 다소 짧음. 생성기 값은 바꾸지 않음 |
| 선박 건조 일정망(Mendeley v8y9gp3kpn, Kyriklidis·Dounias 2023, "실제 선박 건조 프로젝트") | 활동 1,178 · 선후행 1,514 · 공기 208일 · 주공정 36(활동 이름·선종 없음) | 로컬 검사(데이터는 저장소 밖): 엔진 전진 계산이 독립 CPM과 기준 ES 1,178/1,178 일치, 단일 지연(+1·+5·+20일 × 모든 활동 3,534회)의 끝 지연 = max(0, 지연 − 총여유) 전부 일치, 회당 약 2ms |

### 9. 출처와 이용 조건

- 비용·일정 파라미터의 근거(공개 기사·문헌·공시, 가정)는 `params/cost_v1.yaml`에 값마다 적었다. 문제 규모·차별점·가정값의
  공개 근거와 검증 상태(원문 확인/2차)는 [`docs/data.md`(공개 근거)](#공개-근거)에 모았다.
- AI Hub 데이터(배관 계장도 등)는 이 저장소와 데이터에 들어 있지 않고 외부 API로 보내지 않는다(AI 허브 이용정책).
- 선급 규칙은 식의 형태와 조항 번호만 인용하고 원문은 싣지 않는다.

### 10. 다시 만들기

```bash
uv run python scripts/generate.py                       # data/synthetic/20261020/ (지도·설계변경·CSV)
uv run python scripts/generate_nl.py                    # 자연어 문장 분할
uv run python scripts/export_template.py <출력.xlsx>     # 지정 양식 엑셀
```

## 생성기

생성기는 `ripple.generator`다. 같은 시드와 설정(`generator/config.yaml`)이면 바이트 단위로 같은 결과(`data/synthetic/<시드>/`의
CSV·JSON과 `GraphSnapshot` 한 벌)를 낸다. 엔진(`ripple.engine`)을 import하지 않는다(평가용 숨긴 모델의 독립성,
`tests/checks/layers.py`가 검사).

### 1. 선박과 범위

- 선종: 15.8만 DWT급 수에즈막스 원유운반선(이중선체). 계약가·인도일은 설정값이고, 지체상금 조건은 호선별 `ld_terms`가 없으면 `params/cost_v1.yaml` 기본값을 쓴다.
- 호선: 기본 1척(`S-001`). 동형선 2척(`S-001`, `S-002`) 모드는 설정으로 켠다(두 번째 호선은 공정이 약 8주 늦다).
- 구역 3개, 블록 14개(호선당). 화물탱크 구역은 No.3 COT 블록 7개로 대표한다.

| 구역 | 블록 ID | 이름 |
|---|---|---|
| 화물탱크(ZCT) | B31P · B31S | No.3 COT 이중저 좌·우 |
| | S31P · S31S | No.3 COT 선측 좌·우 |
| | D31C | No.3 COT 갑판 |
| | L31C | 중심선 종격벽 |
| | T31C | No.3 COT 횡격벽 |
| 기관실·펌프룸(ZER) | E11C · E21C | 기관실 이중저 · 기관실 측부·플랫 |
| | P11C | 펌프룸 |
| | A11C | 선미(프로펠러 보스·러더) |
| 선수부(ZFO) | F11C · F21C · F31C | 구상선수 · 선수 평형수탱크 · 선수루 갑판 |

블록 ID 형식은 `{위치 문자}{구획 번호}{순번}{P/S/C}`이다. 공개 표준이 없어 가정한 형식이다.

- **경계 조건**: 구역마다 출구 이정표(구역 탑재 완료)와 인도일까지의 여유 F_z, 이미 예상되는 인도 지연 E를 만든다(`docs/domain.md` 5절). 시험용으로 경계 조건을 일부러 빼는 설정도 둔다.

### 2. 부재

- 선체 블록: 판 10~16, 보강재 12~18, 브라켓 4~8. 판 두께는 10~20mm(0.5mm 단위), 강종은 AH36 위주에 A·AH32 일부.
- 판·보강재에는 강도 사전검사용 구조 속성(보강재 간격 0.6~0.9m, 스팬 2.5~5m, 설계 수두 8~25m)을 넣는다.
- 배관(P11C·E21C 중심): 계통 2개(화물 스트리핑, 평형수). 스풀 20~40, 밸브 10~20, 서포트 10~20.
  - 계통마다 이웃 블록으로 이어지는 스풀 2~3개(화물 스트리핑 → T31C, 평형수 → E11C, 번호 101부터 — 주 블록 번호·
    문장 사례의 '지도에 없는 번호'와 겹치지 않게)와 계통 장비(펌프) 하나(주 블록, 첫 스풀과 배관 연결).
  - 관통마다 관통 칼라 부재 하나(관통 판의 블록, 판에 필릿 용접 · 배관과 관통, 규격 `CL-DN…` 부속).
  - 밸브·부속 분류 이름은 일반 공학 용어(게이트·볼·버터플라이·체크·글로브 밸브, 리듀서, 플랜지, 스트레이너 등)를 쓴다. AI Hub 71443 원본은 쓰지 않고 분류 이름만 참고한다.
  - 부재 이름·도면 제목·규격 설명·설계변경 제목에는 현장 이름(계통은 설정 `label` → 지도 `pipe_systems`, 밸브 종류는 한국어)을 쓴다.
  - 계통 키(`cargo_stripping`·`ballast`)와 밸브 종류 키(`globe` 등)는 `Part.system`·`pid_class`·규격 ID(`VL-GLOBE-…`)에만 남긴다.
- 호선당 부재 약 500~600개(예선 계획서의 '부품 500~1,000'), 발주 약 100건. 동형선 모드에서 두 배.
- 블록 난이도 입력: 블록마다 형상(평·곡·선수미, 설정)과 의장품·전장품 수(밀도 수준 낮음·보통·높음의 강재 t당 개수 범위에서
  블록마다 뽑음 — 기관실·펌프룸 높음, 화물탱크 낮음, 가정). 재작업 난이도 계수(`docs/engine.md`(비용·일정) 4-4)에 쓴다.
- 다른 분야 도면(`Part.secondary_drawing_ids`): 관통 판·칼라 → 계통 배관도, 서포트 → 블록 선체도, 장비 → 계통 배관도,
  경계 스풀 → 그 블록 선체도. 설계변경 사전 점검(분야 간 도면 미반영)에만 쓰고 도면 개정(R-D01)은 자기 도면만 본다.

### 3. 연결

- 맞대기 용접: 같은 블록 안 인접 판, 블록 이음부를 사이에 둔 판
- 필릿 용접: 보강재·브라켓 → 판
- 관통: 배관 스풀이 격벽판을 지남(T31C·P11C 경계)
- 지지: 서포트 → 스풀
- 배관 연결: 스풀 ↔ 스풀, 스풀 ↔ 밸브, 스풀 ↔ 장비, 블록 경계를 넘는 스풀 ↔ 스풀
- 칼라: 칼라 ↔ 판 필릿 용접, 칼라 ↔ 배관 관통
- 끊긴 연결(R-X01 시험용)을 일정 비율로 만든다.

### 4. 자재·발주·재고

- 규격: 판(강종 × 두께), 형강, 배관(구경·스케줄), 밸브(분류 × 구경 × 압력 등급), 부속, 장비. 배관·밸브·서포트 규격에는 연결 규격(구경 DN·압력 등급)을 채운다(R-P01 판정용).
- 발주:
  - 강재는 블록 × 자재군(판·형강·브라켓)마다 규격 1~3개씩 묶어 발주한다(같은 블록 안에서도 발주마다 진행 단계가 다르다). 배관은 계통마다 스풀·서포트·밸브를 따로 발주한다.
  - 협력사 구분: 판·형강은 제강사(기자재 공급사), 배관재·밸브·펌프는 기자재 공급사, 브라켓·서포트·칼라 단품은 사외 협력사
    (`SupplierKind.PARTS`). 경계 스풀·펌프·칼라 발주는 기본 발주 번호 뒤에 붙인다.
  - 발주 예정일 = 그 자재를 쓰는 공정 착수일 − 리드타임 − 여유(1~3주). 자재 확보·제작 착수 일수는 리드타임의 비율로 정한다(자재 확보 ≤ 제작 착수 ≤ 리드타임).
- 단계 기록:
  - 기준일 이전 단계는 확인된 진입일과 기준일 현재 상태 관측(발주대장을 기준일에 내보낸 것 — 빈 칸은 아직 그 단계 전)을 넣는다. 일부 발주는 진입일 대신 과거 관측(상태·확인일)만 넣는다.
  - 관측만 있는 발주, 아무 정보도 없는 발주('판단 불가' 시험용)를 일정 비율로 만든다.
- 재고: 다른 블록용으로 입고됐지만 가공 전인 강재 로트 몇 개(잉여 자재 전용 시연용).

### 5. 공정·일정

- 블록 공정: 소조립 → 판넬조립 → 대조립 → 선행의장 → 선행도장 → PE → 탑재. 기간은 블록 중량에 비례(설정의 범위).
  - PE: 설정 `pe_offset`에 PE를 두고 소조립~선행도장은 그 앞으로 거꾸로 배치하며, 탑재는 PE 뒤에 둔다.
  - 수행 주체: 탑재는 직영, 그 밖의 블록 공정은 확률 0.6으로 그 공정을 맡는 사내 협력사 작업반(4곳, 가상) 하나, 아니면 직영.
- 탑재 순서: 기관실 이중저 → 화물탱크 → 선수부. 이정표: 구역 탑재 완료(구역마다), 진수, 시운전(인도 30일 전), 인도.
  후행 의장·선체도장은 공정으로 만들지 않는다(일정 계산은 구역 출구까지, 인도는 경계 조건).
- 시나리오 기준일(기본 2026-10-20)에서 데모가 성립하도록 일정을 배치한다.
  - T31C(No.3 COT 횡격벽): 대조립 중, 판 발주는 입고·가공 완료 → 데모 2
  - P11C(펌프룸): 미착수, 밸브 발주는 미발주 → 데모 1(승인 가능)
  - 나머지 화물탱크 블록: 일부 강재 입고, 일부 미착수
  - 선수부: 미착수(영향이 닿지 않는 대조 구역)

#### 6-1. 숨긴 실제 비용·지연 (`actuals-v5`, `ripple/generator/actuals/`)

평가(E2a·E2'·E7, 4단계)의 정답이다. 생성기 안에 두고 엔진을 import하지 않는다(엔진과 같은 명세의 다른 구현). 결과
(`ActualOutcome`: 항목별 금액·미반영 비용·총액·구역 출구 지연·늘어난 인도 지연)는 생성기 dataclass이고 지도·CSV·JSON·스냅샷
ID에는 들어가지 않는다. 아래 숫자는 엔진과 비교하기 전에 정했고, 바꾸면 버전을 올리고 이유를 남긴다.

- **참 날짜**: 발주마다 생성 때 정한 단계 진입일(발주·자재 확보·제작·입고, 입고에 0~5일 잡음)을 기준일 뒤까지 그대로 쓴다(지도에는 기준일까지의 근거만).
  블록 공정은 기준일까지의 실제 착수·완료, 그 뒤는 착수 하한 = 계획 착수 + 정수 U{0..3}일(공정마다 시드)로 `docs/engine.md`(비용·일정) 6-2 전진 계산.
- **참 파라미터**: `params/cost_v1.yaml`의 키마다 삼각분포(최소, 대표값, 최대), 범위가 없으면 대표값. `po_cancel_ratio.*`·`rework_multiplier.*`는 묶음마다
  분위수 하나를 같이 써 단계 순서대로 줄지 않는다.
- **새 규격 리드타임**:
  - 판 = 표준 + **실제 입고 지연**(분위수 표에서 U(0, 1)을 선형 보간, 일 단위 반올림). 표 `PLATE_DELAY_DAYS`는 비공개 현업 강재 재고 집계
    (판 입고일 − 계약납기일, 1·5·10·…·95·99백분위: −45 · −24 · −18 · … · +2(중앙) · … · +14(90) · +16(95) · +22(99)일)다. 우리가 정한
    범위를 쓰면 E2' 일정 위험 판단(결정 93)이 그 범위를 다시 재는 순환이 되기 때문이고, 지표를 재기 전에 정했다(`docs/evaluation.md` 3절).
  - 형강·배관·밸브·장비 = 표준 × U(0.9, 1.2)(가정). 형강은 집계의 입고 지연이 둘로 갈려(일찍 −35일·늦게 +84일) 자료 성격이 불명확해 쓰지 않는다.
  - 외자재(엔진과 같은 규칙): 리드타임이 생산 리드타임(새 규격 표준·파라미터)이고 사는 규격이 외자재면 **참 운송
    일수**(참 파라미터 `transport_days.<방식>`, 일 단위 반올림)를 더한다. 위 변동은 생산분에만 곱하고, 원래 발주의 리드타임을
    쓰면(이미 운송 포함) 더하지 않는다.
- **항목**: 자재비 차이·새 부재 제작 공수(C-02)·발주 변경 손실·급발주 할증·블록 재작업·도장 뒤 고정 항목(C-04)·작은 작업·지체상금·
  자재 전용(`docs/engine.md`(비용·일정) 4절과 같은 구분).
  - 블록 재작업(엔진과 같은 식)은 공정마다 공수 × 단계 배수 × 블록 난이도 계수 × 그 공정 수행 주체 단가(작업반 ·
    직영 · 모르면 블록 규칙)이고, 블록 단계가 선행도장 이후면 도장 뒤 고정 항목을 따로 더한다. PE는 블록 공정 사슬에 있다.
    의장품(배관 스풀·밸브·서포트·장비) 중량은 선행의장 공정부터만 넣는다(actuals-v5, 엔진 0.12.0과 같은 규칙).
  - 도면 개정 공수는 배관도면 `minor_work_hours.drawing_revision_piping`, 그 밖 도면은 `drawing_revision_per_drawing`(actuals-v5).
  - 지연 파급 비용(엔진 4-11)은 총액 밖이라 숨긴 모델 실적에 넣지 않는다.
  자재비 차이·전용만 음수가 될 수 있다.
  - 항목마다 곱 잡음 lognormal(0, σ = 0.15), 사례마다 확률 0.1로 미반영 비용 = U(0.1, 0.4) × 양수 항목 합.
  - 강재(판·형강) 발주 변경 손실의 비율은 참 취소·변경률과 참 강재 상한(`steel.max_cancel_loss_ratio`) 중 작은 값이다(`docs/engine.md`(비용·일정) 4-2와 같은 규칙).
- **시드**: 잡음·미반영 비용·새 규격 리드타임은 생성 시드·설계변경 ID·항목(또는 규격)으로만 정한다 — 확정일·보류와 무관한 같은 세계에서 결정만 바꿔
  비교한다(E7).
- **일정**: 참 기준 일정과 참 변경 일정(재작업 일수를 운반 공정에, 새 자재 도착 + 1·재작업 완료로 탑재 관문, 보류한 발주 품목의 미뤄진 입고일을 착수 전
  소비 공정의 제약으로)을 같은 망에서 계산한다.
  - 구역 출구 지연 = 두 일정의 출구 완료일 차이. 인도 지연 = `docs/engine.md`(비용·일정) 6-4처럼 두 일정 각각의 계획 대비 늦음 − 여유로 구한 D의 차이.
    경계 조건 없는 구역 출구가 늦으면 계산하지 않는다.
  - 잉여 자재 전용은 확정일부터 60일 안의 착수 전 수요를 본다.
- **확인 모드**(`oracle=True`): 대표 파라미터, 잡음·미반영 비용 0, 착수 지연 0, 리드타임 표준 그대로, 미발주 품목의 앞으로의 발주일은 지도의 계획 발주일 —
  엔진과의 차분 검사용(`tests/checks/actuals.py`: 개발 200건 중 판단 불가가 없는 194건에서 총액 ±1%·출구 지연 일치 194/194, 엔진 0.11.0·actuals-v4·지도 v4).

#### 7-1. 문장 생성 규칙

- **사전**: `ripple/generator/lexicon.yaml`의 `nl-lexicon-v2`는 생성기 전용 표면형이다. 판·보강재·브라켓·스풀·밸브·서포트, 블록 이름 조각, 배관 계통·밸브 종류,
  연산·사유·맺음말을 묶는다. 계통 별칭에는 계통 키 표기를 넣지 않는다. 생성기는 엔진·해석기 사전을 읽지 않는다.
- **부재 표기**:
  - 블록을 포함한 코드(`T31C-PL-007`, 약 30%) 또는 블록 이름·종류·번호(`3번 탱크 횡격벽 판 7번`)로 적는다.
  - 복수 대상은 쉼표 목록이나 연속 번호 범위로 적는다. 조각은 각 부재를 구별하는 코드 접미부 또는 번호다.
  - 추가 연산은 블록·종류·규격·수량·부착 판을, 경로 변경은 빼는 스풀·더하는 규격 목록·관통 판을, 관통부는 판·배관·지름을 적는다.
- **값 표기**:
  - 두께는 절대값, 전후, 증감, 비율 중 하나로 적는다. 강종·장비 사양은 절대값 또는 전후로 적는다.
  - 장비 사양의 절대값은 절반쯤 바뀌는 속성만 적는다('볼 밸브로', 'DN200 10K 체크 밸브로' — 그 조합이 지도에서 규격 하나일 때만).
  - 경로 변경의 같은 규격 여러 개는 '규격 N개'로 한 번 적는다.
  - 길이 치수는 지도에 원래 길이가 없으므로 생성된 변경 전 값을 전후·증감·비율 표현에 반드시 적는다.
  - 전후 수치가 드러나는 조각은 값 표현 전체를 감싸고, 조각의 `value`는 변경 후 정답 값이다.
  - 두께·강종·치수·사양은 약 3%에서 값을 생략한다.
- **사유·어순**: 사유는 약 70%에 적고 `intent_stated`에 표시한다. 값이 연산을 드러내는 두께·강종·사양의 연산 단서는 약 10%에서 생략한다.
  사유는 앞·뒤·괄호에 놓고, 일부 문장은 값을 대상 앞에 놓는다.
- **잡음**:
  - 글자 잡음은 정답 조각 밖에만 적용한다. 사전의 흔한 오타 또는 한글 글자 빠짐·겹침·뒤바뀜, 절 사이 띄어쓰기, 어순, 약어, 코드 대소문자를 `noise`에
    기록한다. 숫자·코드 안에는 오타를 넣지 않는다.
  - 전후 표현 약 2%는 변경 전 값을 지도와 다르게 적고 `stale_before`를 기록하되, 정답 연산은 지도 값을 유지한다(치수는 지도에 값이 없어 넣지 않는다).
  - 약 4%에서 부재 번호 하나를 같은 블록·종류의 지도에 없는 번호(가장 큰 번호 바로 위 1~3)로 바꾸며 정답 ID도 그 번호로 바꾼다. 해당 조각만
    `exists=False`다.
- **조립**: 조각의 `start:end`는 모든 표면형·잡음 조립이 끝난 문장에서 계산한다. 각 사례는 `sub_rng(seed, "nl", split.value, str(i))`로 결정되어
  분할과 생성 건수의 영향을 받지 않는다.

### 8. 엑셀 변형(가져오기 시험용)

- 같은 데이터를 BOM·발주대장·공정표 엑셀로 내보내고, 지저분한 변형을 만든다: 머리글 이름 바꾸기(품번/부품번호/Part No.), 병합 셀, 단위 혼재(mm·t 표기), 빈 행, 코드 중복, 발주번호 누락, 상태 열(발주·자재 확보·제작·입고)과 확인일 열.
- 변형마다 '정답 매핑'을 함께 저장해 E6(매핑·연결 정확도)과 열 문 판단(E8)을 잰다.

### 9. 평가용 정답의 독립성

- 평가 100건의 영향 정답은 생성기가 만든 연결 구조에서 나온다. 엔진 규칙과 같은 의미 체계를 쓰므로, 이 집합은 **데이터 잡음(끊긴 연결·잘못된 코드)에 대한 강건성과 where-used 기준선 대비 차이**를 재는 데 쓴다.
- 의미 정확도는 사람이 엔진 코드를 보지 않고 계산한 경계 사례 30건으로 잰다(`docs/gate_cases.md`).

### 10. PE·작업반·협력사·경계 배관·다른 분야 도면

- **만드는 것**: PE 공정(블록마다)·시운전 이정표, 블록 형상·의장품·전장품 수, 사내 협력사 작업반 4곳과 공정 수행 주체,
  사외 협력사(단품) 공급사·펌프 제조사, 블록 경계 배관(계통마다 이웃 블록 스풀 2~3개)·관통 칼라·계통 장비, 다른 분야 도면.
  이 값들은 따로 난수원을 써서 뽑고(블록·계통·공정 ID별), 이 발주는 기본 발주 번호 뒤에 붙인다. 그래서 기본 부재 ID·속성,
  발주 번호·품목·단계 날짜, 소조립~선행도장 계획·실적 날짜(기준일 블록 단계), 설계변경 이력 300건(번호·연산·대상)과 문장
  사례를 흔들지 않는다.
- **설계변경 대상 후보**: 설계변경·문장 사례의 배관 대상 후보는 계통의 주 블록(설정 `piping.systems[].block`) 부재로
  고정해(`ripple/generator/ecn.py` `Catalog`) 이웃 블록 스풀·칼라·장비를 대상으로 삼지 않는다 — 시연 고정점(ECN-D-0043 평형수
  배관 경로·후행 설치 선택지, ECN-D-0119 B31P 판 두께·더 저렴한 대안, ECN-D-0067 결재함 더 저렴한 대안)과 시드 각본
  (`ripple/api/demo_plan.py`)의 이야기가 그대로 성립한다(검사 `tests/checks/generator_v3.py`). 이력을 다시 뽑는 판에서는 이 부재도
  대상 후보에 넣는다.

### 11. 외자재 규격

- 설정 `imports`(`ripple/generator/imports.py`): (배관 계통, 부재 종류)마다 그 계통 주 블록 부재가 쓰는 **규격**을
  외자재로 바꾼다 — 원산지 외자재 · 운송 방식 하나 · 생산 표준 리드타임(운송 제외, 가정: 밸브 45일 = 밸브 발주 리드타임 범위
  끝, 펌프 180일 = 장비 발주 범위 가운데).

  | 대상(기준 시드의 발주) | 규격 | 운송 방식 | 고른 이유(가정) |
  |---|---|---|---|
  | 평형수 밸브(E21C, PO-0133) | VL-BUTTERFLY·CHECK·GATE-DN200-10K | 선박 | 계획 조달 기자재의 흔한 경로 |
  | 화물 스트리핑 펌프(P11C, PO-0135) | EQ-PUMP-CS-DN100 | 항공 | 작은 펌프(DN100) — 두 방식이 모두 지도에 있게 |
  | 평형수 펌프(E21C, PO-0137) | EQ-PUMP-BW-DN200 | 선박 | 큰 장비 |

- **국산으로 두는 것**: 화물 스트리핑 밸브(P11C, PO-0130) — 관문 2단계 사례(G2-003·004)와 시연 1(승인 가능)이 쓰는 발주다.
  부재·발주(발주의 리드타임은 이미 운송 포함)·날짜·설계변경 이력·난수열은 외자재 설정에 따라 달라지지 않는다(검사
  `tests/checks/transport.py`가 외자재 설정을 뺀 생성 결과와 비교).
- **계산에 미치는 것**: 새로 발주하는 리드타임이 외자재 규격의 표준이면 운송 일수가 붙는다. 규격 단위라 화물 스트리핑
  밸브를 평형수 밸브 규격(DN200 10K)으로 바꾸는 설계변경도 외자재 새 규격이 된다.
  - 개발 200건 중 평형수 밸브 발주를 건드리는 설계변경 21건(평가 100건 중 5건), 새 규격이 외자재인 설계변경 14건(평형수 8 ·
    화물 스트리핑 6, 평가 7건). 외자재 설정을 뺀 생성과 견주면 대표 총액·구역 출구 지연·마감일·판정 수준은 200건 모두 같고,
    14건은 일정 위험 출구 지연(평형수 43일, 화물 스트리핑 84일)이 커지며, 평형수 8건에는 E21C 탑재 지연(판정 이유 '블록 탑재
    지연 가능'·출구 여유 52일·후행 설치 선택지)이 있고, 화물 스트리핑 6건에는 발주 보류 권고가 없다.
  - 시연 고정점 ECN-D-0043·0119·0067·0173은 외자재 설정의 영향을 받지 않는다(대상이 외자재 규격이 아님).

### 12. 시연 합성 지도(시연 영상 · 공개 시연 배포)

- 설정 `generator/demo_map.yaml` = `extends: config.yaml` + `relations`(`ripple/generator/relations.py`). 기본 지도를 설계변경
  이력까지 다 만든 뒤 관계만 더한다 — 난수를 쓰지 않아 선체·블록·부재·연결·발주·재고·도면·공정 날짜·설계변경 300건이 기본
  지도와 같고 지도 ID만 다르다(검사 `tests/checks/demo_map.py`). 기본 지도·평가 관문은 이 설정을 쓰지 않는다.
  시연 영상·README 그림·소개 화면 예시(`scripts/export_showcase.py`)와 공개 시연 배포(2026-11-04부터 Railway api
  `RIPPLE_SYNTHETIC_MAP=demo`)가 이 지도를 쓴다.
- 지도 이름은 '시연 합성 지도'(설정 `relations.name`, '합성'이 없으면 설정 오류). 앱은 `RIPPLE_SYNTHETIC_MAP=demo`일 때만 기본 지도
  자리에 깐다(`docs/operations.md`(서비스) 6절).
- **탑재 순서**(`erection_after`, No.3 COT 화물창 링 — 이중저를 먼저 앉히고 그 위에 격벽·선측을 세운 뒤 갑판으로 덮는다):

  | 후행 블록 탑재 | 먼저 끝나야 하는 탑재 |
  |---|---|
  | T31C 횡격벽 | B31P · B31S 이중저 |
  | L31C 중심선 종격벽 | B31P · B31S 이중저 |
  | S31P 선측 좌 | B31P 이중저 좌 |
  | S31S 선측 우 | B31S 이중저 우 |
  | D31C 갑판 | T31C · L31C · S31P · S31S |

  선후행은 lag 0이고, 기본 지도의 계획 날짜가 이 순서와 맞는다(후행 탑재 착수 계획 ≥ 선행 탑재 완료 계획 — 어긋나면 생성기가
  멈춤). 엔진은 이 선후행으로 일정을 다시 계산하고, R-S01 (라)(`docs/engine.md`(비용·일정) 7절)로 늦어진 다른 블록 탑재마다 일정
  지연 영향을 낸다.
- **ECN-D-0119(B31P 판 두께 17.0→20.0mm, 3장, 기준일 확정)에서 달라지는 것**(엔진 0.15.0으로 잰 값, 0.15.1에서도 같음):

  | | 기본 합성 지도 | 시연 합성 지도 |
  |---|---|---|
  | 블록 사이 관계 | B31P → L31C 맞대기 용접 | + B31P 탑재 → L31C · T31C · S31P 탑재 선행(1차), L31C 탑재 → D31C 탑재 선행(2차) |
  | 영향 수 | 20 | 24(다른 블록 탑재 일정 지연 4) |
  | 늦어지는 탑재 | B31P 67일 | B31P 67일 · T31C 60일 · L31C 54일 · S31P 46일 · D31C 9일 |
  | 화물탱크 구역 출구 지연 | 3일 | 9일(일정 위험 20일 → 26일) |
  | 총변경비용 · 판정 · 결정 기한 | 43,337,303원 · 경고 · 기준일 + 7일 | 같음(인도 여유 안이라 지체상금 없음) |

  - 엔진 0.15.1(이미 탑재한 블록의 관문·선상 설치 lag는 구역 출구에만, docs/engine.md(비용·일정) 6-3)은 이 표의 값(기준일 확정)을
    바꾸지 않는다. B31P 탑재가 시작된 뒤의 판정일(곡선 2026-11-15부터)만 다음 블록 탑재로 관문이 번지지 않아 구역 출구 지연·
    총액이 작거나 같아진다.
  - 개발 200건 가운데 영향 목록이 달라지는 건 12건(B31P·B31S 이중저 판 변경 — 다른 블록 탑재 지연 영향이 더해짐)이고,
    총변경비용·판정 수준·결정 기한은 200건 모두 같다. 구역 출구 지연이 달라지는 건 ECN-D-0119 하나다.
  - 같은 도면·같은 발주로 블록을 건너는 관계는 더하지 않았다: 지금 규칙(R-D01·R-T01)은 도면·발주 품목에서 멈춰 다른 블록으로
    이어지지 않아, 자료만 더하면 화면에 보이지 않는 관계가 된다.

### 4. 쓰지 않는 것(이유)

- 1:10:100 법칙 — 조선 실측 근거 없음(품질관리 일반 경험칙).
- '최종 조립장 8배·진수 뒤 12배'(Stott 2018 재인용) — 원문 미확인.
- 특허 예시 숫자(도면당 12시간 등) — 가상 예시이고 예시끼리 맞지 않음.
- 외국인 인력 비중 등 기준이 제각각인 통계 — 출처마다 정의가 달라 숫자로 인용하지 않음.

  새 규격 리드타임 변동 하나로 생기는 구역 출구 지연을 대표값 일정이 놓쳐, 일정 위험 범위(결정 93)를 정하는 데 씁니다.
