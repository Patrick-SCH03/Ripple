# 운영 명세

서비스 입구(소개 화면·로그인·계정과 역할·작업 공간과 지도 전환, 서비스 편)와 Railway 라이브·오프라인 노트북의 배포·운영 절차(배포 편)를 적는다.
코드 주석은 `docs/operations.md`(서비스) 2절처럼 편 이름과 절 번호로 가리킨다.

## 서비스

웹에 들어가면 공개 소개 화면이 있고, 로그인한 뒤 업무 화면을 쓰는 서비스 입구다. 라이브 배포는 `docs/operations.md`(배포).

### 1. 범위

- 포함: 공개 소개 화면(`/`), 로그인(`/login`), 업무 화면(`/app`)과 모든 업무 API를 로그인 뒤로, 역할(관리자·파트장·본부장·담당자·체험) 권한, 구성원 관리(관리자), 첫 로그인·초기화 뒤 비밀번호 바꾸기, 체험 계정, 배포 이미지(화면 Caddy·API)와 컨테이너 스모크.
- 범위 밖: 외부 로그인(SSO), 자유 가입, 메일 발송, 2단계 인증, 승인 기록·감사 로그(`docs/records.md`), 외부 LLM 사용량 한도(`docs/input.md`(외부 AI)), 비서 대화 소유자 검사(대화 ID는 무작위).

### 2. 계정·세션·권한 (`ripple/auth`, `ripple/store/accounts.py`, `ripple/api/security.py`)

관리자 역할(admin)은 화면에서 **팀장**으로 보인다. 결재는 **결재선**(`docs/records.md`(기록·결재) 14절)이다 — 추가 비용 건은 파트장(`part_lead`) → 팀장 → 본부장(`executive`)이 차례로 승인하고 팀장은 파트장·본부장 단계를 전결할 수 있으며, 무비용 건(비용이 도면 개정뿐)은 담당자가 처리한다. 기록·검토 요청·실행·상태 갱신은 담당자 일이다(계약 1.24.0).
파트장·본부장 역할을 쓴 계정 파일은 그 역할을 모르는 이전 이미지가 읽지 못해 시작을 멈춘다(배포 4절).
개발 모드(`RIPPLE_AUTH=off`)는 역할과 무관하게 모든 권한이다.

| 할 일 | 팀장 admin | 파트장 part_lead · 본부장 executive | 담당자 member | 체험 demo |
|---|---|---|---|---|
| 지도 보기 · 분석 · 영향 · 대안 · 비서 · 샘플 | ✓ | ✓ | ✓ | ✓(합성 데이터만) |
| 문서로 넣기(문서·변경 리스트 → 확인표 → 분석, `docs/input.md`(문서 접수), 1.27.0) | ✓ | ✓ | ✓ | ✓(합성 데이터만) |
| 지도 엑셀 내려받기 | ✓ | ✓ | ✓ | 합성 데이터 지도만 |
| 분석 결과 엑셀 내보내기(`POST /api/analyses/export`, 상세의 '엑셀로 내보내기') | ✓ | ✓ | ✓ | 합성 데이터만 |
| 결재 대장 엑셀(`GET /api/manage/export`, 결재·현황의 '엑셀로 내보내기') | ✓ | ✓ | ✗ | ✗ |
| 지도 전환 · 엑셀 가져오기·확정 | ✓ | ✗ | ✗ | ✗ |
| 구성원 관리(역할 · 비밀번호 초기화 · 사용 중지 · 삭제) · AI 호출 기록 | ✓ | ✗ | ✗ | ✗ |
| 기록 남기기 · 검토 요청 · 무비용 담당자 처리 · 실행 시작 · 종료 · 상태 갱신(`docs/records.md`) | ✗ | ✗ | ✓ | ✗ |
| 승인 · 반려 · 보류(결재선의 자기 단계) | ✓(팀장 단계 + 파트장·본부장 단계 전결) | ✓(자기 단계만) | ✗ | ✗ |
| 검토 취소 | ✓ | ✗ | 요청한 사람 | ✗ |
| 감사 로그 확인 · 결정 도우미 · 상태 갱신 이력 | ✓ | ✓ | ✗ | ✗ |
| 결재·현황(`/app/manage`: 결재함(자기 단계 건)·현황·성과·관리) | ✓ | ✓ | ✗ | ✗ |
| 결재 상태 · 이력 보기 | ✓ | ✓ | ✓ | 합성 데이터 기록만 |
| 비밀번호 바꾸기 | ✓ | ✓ | ✓ | ✗ |

- **결재 단계 없음**(1.25.0): 1.24.0의 계정 결재 단계(`approval_level`, 계정 파일 형식 판 3)는 없앴다.
  - 판 3 파일의 그 칸은 읽을 때 버리고 쓸 때 넣지 않으며 판 번호는 3 그대로다(1.24.0 코드로 되돌려도 읽힘).
  - 사용 중인 팀장이 0명이 되는 변경은 409 `last_admin`.
- **구성원 삭제**(`DELETE /api/accounts/{id}`, 관리자, `ripple/auth/members.py` `delete_account`): 계정을 지우고 그 계정의 세션을 모두 끊는다(지운 뒤에 남은 세션도 계정이 없어 무효).
  - 거절: 내 계정 403(`forbidden`, '내 계정 삭제 불가') · 빠른 로그인 고정 계정 403(고정 계정 잠금과 같은 규칙·문구) · 지우면 사용 중인 팀장이 0명이 되는 계정 409 `last_admin`(내 계정을 못 지우니 개발 모드에서만 닿음) · 없는 계정 404.
  - **기록의 이름은 그대로**: 기록·검토 요청·결재·감사 줄은 그때의 아이디·이름·역할(`Actor`)을 담고 있어 계정을 지워도 바뀌지 않는다(고칠 수 없는 사슬, 사슬 검증도 그대로). 지운 사람이 올린 검토도 팀장이 결정할 수 있다.
  - **지운 아이디는 다시 쓰지 않는다**: 기록이 사람을 아이디로 가리키므로(이력의 '누가'·자기 결정 금지) 같은 아이디로 새 사람을 만들면 두 사람이 한 아이디로 섞인다. 그래서 지운 아이디를 계정 파일의 `retired_ids`에 남기고, 구성원 추가는 409(`account_exists`, '삭제된 계정의 아이디 재사용 불가 · 다른 아이디 필요'), 첫 관리자 변수·`python -m ripple.auth add-admin`도 만들지 않는다. 실수로 지웠으면 다른 아이디로 새로 만든다.
  - **계정 파일 형식 판 4**: 지운 계정이 하나라도 있으면 판 4(`retired_ids`)로 쓰고, 없으면 판 3 그대로 쓴다(옛 이미지로 되돌려도 읽힘). 판 4 파일로는 이전 이미지가 시작하지 않는다 — 되돌릴 때는 볼륨 백업도 함께(배포 4절). 세션 파일은 판 3 그대로.
- **저장**: `RIPPLE_DATA_DIR`(지도 저장소와 같은 볼륨)의 `accounts.json`·`sessions.json`, 원자적 쓰기 + 잠금(서버 1대 전제).
  - 계정 파일이 손상되면 시작하지 않는다(빈 계정으로 시작해 첫 관리자 변수가 관리자를 새로 만들지 않게). 세션 파일 손상은 모두 다시 로그인.
- **비밀번호**: 표준 라이브러리 scrypt(N=2^15, r=8, p=1, 솔트 16B, `maxmem` 64MiB — N·r만으로 32MiB라 OpenSSL 기본 상한을 넘는다), 매개변수를 해시에 함께 적고 상수 시간 비교.
  - 규칙 10~128자. 거절: 아이디 그대로이거나 아이디에 3자 이하만 붙인 것(대소문자 무시 — 아이디 + 4자 이상은 받음), 서로 다른 글자가 4개 미만(같은 글자 반복), 흔한 비밀번호, 앞뒤 공백(`ripple/auth/passwords.py` `password_problem`).
  - 해시 계산은 동시에 2개까지(대기 10초 넘으면 503). 없는 아이디도 가짜 해시를 계산해 응답 시간으로 계정 유무를 알 수 없게 한다.
- **세션**: 서버 쪽(무작위 32B 토큰, 파일에는 SHA-256만). 관리자·담당자 12시간, 체험 2시간 절대 만료.
  - 비밀번호 바꾸기·초기화·사용 중지·역할 변경은 계정의 **세션 판**(`session_version`)을 올리고 그 계정의 세션을 지운다(바꾼 본인은 새 세션).
  - 세션은 만들 때의 판을 갖고 판이 다르면 무효라, 세션 파일 쓰기가 실패하거나 로그인 검증과 관리자 초기화가 엇갈려도 옛 세션이 살아남지 않는다.
  - 정리는 무효로 만든 판보다 오래된 세션만 지운다(`delete_for(below=)`) — 계정 변경과 정리 사이에 새 판으로 만든 정상 세션을 늦은 정리가 지우지 않게.
  - 계정은 잠금 안에서 지금 사본을 읽어 바꾼다(검증하려고 먼저 읽은 사본으로 덮어 동시 변경을 지우지 않게).
  - 쿠키 `ripple_session`: HttpOnly · SameSite=Strict · Path=/ · Secure(`RIPPLE_COOKIE_SECURE`, 기본 켬 — 노트북 compose는 http라 끔).
- **출처 검사**: 상태를 바꾸는 `/api` 요청(POST·PUT·PATCH·DELETE)은 Origin이 있으면 요청 Host와 같아야 한다(다르거나 `null`이면 403 bad_origin). Origin이 없는 요청(서버 간·검사 도구)은 통과 — SameSite=Strict 쿠키가 다른 사이트 요청에 실리지 않는다.
- **실패 제한**: 아이디마다 15분 안에 5번 틀리면 429(Retry-After). 지금 비밀번호 확인(비밀번호 바꾸기)도 같은 제한을 따로 둔다.
  - 검사 중인 시도도 센다(최근 실패 + 검사 중 ≥ 5면 429) — 동시에 들어온 요청이 함께 확인을 지나 5번보다 많이 검사되지 않게.
  - 클라이언트 IP는 쓰지 않는다 — Railway 앞단의 X-Forwarded-For·X-Real-IP를 어디까지 믿을지 공식 문서로 정해져 있지 않고, IP로 묶으면 모든 사용자가 한 IP로 보여 한 사람의 실패가 모두를 막을 수 있다.
- **첫 관리자**: 계정 파일이 비어 있고 `RIPPLE_ADMIN_ID`·`RIPPLE_ADMIN_PASSWORD`가 있으면 시작할 때 관리자 1명(첫 로그인 때 비밀번호 바꾸기).
  - 변수가 하나만 있거나 규칙에 어긋나면 만들지 않고 경고 로그, 상태 확인의 `auth.accounts_ready`가 거짓 → 로그인 화면 안내.
  - 로컬·오프라인 도구: `python -m ripple.auth add-admin|reset|list`(숨김 입력).
- **체험**: `RIPPLE_DEMO_LOGIN=on`일 때 저장소 밖 공용 계정 하나. 실데이터를 어떤 경로로도 보지 않는다.
  1. 활성 작업 공간의 유효 데이터 모드가 real이면 체험 로그인·체험 세션의 요청 403(demo_unavailable).
  2. 지도 목록은 지도마다 자기 데이터 모드로 걸러 합성 지도만(실데이터 지도의 파일 이름·호선·규모·품질 리포트가 보이지 않게, 활성 지도가 real이면 목록 자체가 403).
  3. 엑셀 내려받기는 요청한 그 지도의 데이터 모드로 판단. 분석 결과 엑셀은 분석과 같이 처리하는 작업 공간의 유효 데이터 모드로(`get_workspace`).
  - 작업 공간을 쓰는 경로는 `get_workspace` 하나가 권한 검사와 처리할 세대를 함께 정한다 — 검사한 직후 관리자가 실데이터 지도로 바꿔도 그 요청은 검사한 합성 세대로 끝난다.
- **빠른 로그인**(계약 1.30.0, `ripple/auth/quick.py`): `RIPPLE_QUICK_LOGIN=on`(기본 off)이면 로그인 화면에 역할 단추 둘 — '담당자로 들어가기'·'파트장으로 들어가기' — 만 보이고(아이디·비밀번호 입력 칸과 체험 단추는 없다 — **켜져 있는 동안 아이디 로그인은 없다**; 시연은 설계변경 한 건의 영향 추적·계산이 중심이라 10-30부터 팀장·본부장 단추는 두지 않고 결재선은 화면의 진행 표시로만 — API는 네 역할을 그대로 받는다), `POST /api/auth/quick`이 고정 계정(담당자 `quick-member` 김설계 · 파트장 `part-lead` 이파트장 · 팀장 `quick-lead` 박팀장 · 본부장 `executive` 최본부장)으로 로그인과 같은 세션을 준다. 파트장·본부장은 시연 기록 시드의 결재선 가상 계정(7절)과 같은 계정이다(계약 `QuickRole`, 1.33.0 안에서 넓힘).
  - 고정 계정은 처음 누를 때 만든다(비밀번호는 아무도 모르는 무작위 값의 해시, 첫 비밀번호 바꾸기 없음). 네 계정은 서로 다른 사람이라 담당자가 올린 검토를 파트장 → 팀장 → 본부장이 차례로 승인한다(자기 결정 금지 그대로).
  - **고정 계정 잠김**: 방문자가 다음 방문자의 단추를 망가뜨리지 못하게 한다.
    - 구성원 추가·첫 관리자로 네 아이디를 만들 수 없다(409).
    - 구성원 관리(이름·역할·사용 중지·비밀번호 초기화)는 네 아이디를 403(`forbidden`, '시연용 고정 계정 변경 불가')으로 거절하고, 화면은 그 줄에 동작 대신 자물쇠와 이유 한 줄을 둔다.
    - 계정 파일을 손으로 고쳐도 빠른 로그인 때마다 이름·역할·사용 중 상태를 서버 상수(`QUICK_ACCOUNTS`)로 되돌린다.
    - 아이디·비밀번호 로그인은 네 아이디를 늘 거절한다(없는 아이디와 같은 401 문구) — 예전 시드가 `RIPPLE_DEMO_PASSWORD`로 만든 비밀번호 해시가 `part-lead`·`executive`에 남아 있어도 같다(시드가 다음 시작에 지운다, 7절).
    - 같은 이유로 **내 줄**(이름·역할·사용 여부)도 서버가 403으로 거절한다(화면과 같은 규칙). 그래서 사용 중인 팀장이 0명이 되는 409 `last_admin`은 개발 모드에서만 닿는다.
  - **끄면 세션 무효**: 설정을 끄면(체험과 같게) 남은 고정 계정 세션은 다음 요청부터 401이다.
  - **세션 상한**: 인증 없이 만드는 세션이라 고정 계정마다 최근 200개만 남긴다(네 계정 800개 — 전역 상한 1,000개 안). 전역 상한을 넘을 때도 그 계정의 오래된 세션부터 지워 다른 계정의 세션을 밀어내지 않는다. 같은 고정 계정끼리 밀리는 것(누군가 단추를 200번 넘게 누르면 앞서 들어온 방문자가 다시 로그인)은 받아들인 위험이다.
  - **첫 관리자·계정 준비**: 첫 관리자 만들기와 `auth.accounts_ready`는 고정 계정을 세지 않는다 — 시연 뒤 끄고 `RIPPLE_ADMIN_*`를 넣으면 팀장이 생긴다.
  - **위험**: 그 주소에 들어온 누구나 팀장이 되어 승인·구성원 추가·지도 전환까지 할 수 있다. 합성 데이터 시연 배포에서만 켜고, **사내 설치판·실데이터에는 켜지 않는다**(켜면 시작할 때 경고 로그). 꺼져 있거나 개발 모드면 404(quick_unavailable)이고 상태 확인 `auth.quick_login`이 거짓.
  - **팀원·관리자 계정**: 켜져 있으면 로그인 화면에 아이디 로그인이 없다. 팀원 계정·관리자 계정(첫 관리자 `RIPPLE_ADMIN_*` 포함)으로 들어가려면 빠른 로그인을 끈 배포에서 쓴다(끄면 고정 계정 세션은 무효, 팀원 계정은 그대로). 고정 계정 넷은 끈 배포에서 들어갈 수 없다.
  - 시연에 쓴 볼륨을 사내용으로 다시 쓸 때는 `accounts.json`·`sessions.json`을 비우고 시작한다(방문자가 만든 계정이 남지 않게).
- **비밀번호 바꾸기 전**: 내 정보·로그아웃·비밀번호 바꾸기 밖의 모든 API가 403(password_change_required).
- **개발 모드** `RIPPLE_AUTH=off`: 모든 요청을 '개발 모드' 관리자로 처리하고 시작할 때 경고를 남긴다. 상태 확인 `auth.required=false`. 기존 성질 검사와 로컬 개발용이며 이미지·compose·Railway 설정에는 두지 않는다.

#### API (계약 1.16.0, `ripple/contracts/auth.py`)

| 메서드 | 경로 | 권한 | 설명 |
|---|---|---|---|
| GET | `/api/health` | 공개 | 버전 + 빌드 커밋(`build`) + 로그인 설정(`auth`) |
| POST | `/api/auth/login` | 공개 | 아이디·비밀번호 → 내 정보 + 세션 쿠키(401·403·429·503) |
| POST | `/api/auth/demo` | 공개 | 체험 로그인(꺼져 있으면 404, 실데이터 활성이면 403) |
| POST | `/api/auth/quick` | 공개 | 빠른 로그인 `{role: member·part_lead·admin·executive}`(1.30.0, 파트장·본부장은 1.33.0 안에서 더함, 꺼져 있거나 개발 모드면 404, 고정 계정은 상수로 되돌린 뒤 세션) |
| POST | `/api/auth/logout` | 공개 | 세션 지우기 + 쿠키 지움(204) |
| GET | `/api/auth/me` | 로그인 | 내 정보(이름·역할·권한·비밀번호 바꾸기 필요) |
| POST | `/api/auth/password` | 로그인(체험 제외) | 지금·새 비밀번호 → 새 세션(지금 비밀번호가 틀리면 401이 아니라 422) |
| GET·POST | `/api/accounts` | 관리자 | 구성원 목록 · 추가(임시 비밀번호 12자를 이 응답에만) |
| POST | `/api/accounts/{id}/reset-password` | 관리자 | 임시 비밀번호 새로(그 계정 세션 폐기, 내 계정은 422, 빠른 로그인 고정 계정은 403) |
| PATCH | `/api/accounts/{id}` | 관리자 | 이름·역할·사용 여부(내 계정·빠른 로그인 고정 계정은 403, 사용 중인 관리자가 0명이 되면 409 last_admin) |

오류 본문은 `detail = AuthProblem{code, message, retry_after_s}`. 나머지 업무 API는 로그인·보기 권한이 필요하고, 지도 전환·가져오기는 관리자만이다(`ripple/api/routes/snapshots.py` 머리 설명).

### 3. 화면 (`web/src`)

- **경로**(라이브러리 없이 history API, `lib/route.ts`): `/` 소개 · `/login`(`next`는 `/app`으로 시작하는 경로만 — 열린 리다이렉트 방지, `reason`=expired·signed-out) · `/app` 업무 화면(React.lazy로 따로 묶어 소개·로그인이 그래프·차트 묶음을 기다리지 않음).
  - 모르는 경로는 소개로, 로그인한 채 `/login`이면 돌아갈 곳으로, 로그인 안 한 채 `/app`이면 로그인으로(`Root.tsx`).
- **로그인 상태**(`state/useSession.ts`): 시작 때 `GET /auth/me`(401 = 로그인 전, 그 밖의 실패 = 연결 안 됨 + 다시 확인). 첫 확인은 시작 때 세대로만 상태를 정한다.
- **인증 세대**(`api/client.ts`): 로그인·체험·로그아웃·비밀번호 바꾸기(세션 교체)마다 오른다.
  - 요청을 보낼 때와 받을 때 세대가 다르면 그 응답(성공·401·409 모두)을 쓰지 않는다(`session_changed`). 연결 실패와 머리글 뒤 늦게 온 본문도 지난 세대면 버린다(`staleCheck`).
  - 세션을 바꾸는 요청이 진행 중일 때 옛 쿠키로 나간 요청의 401도 지난 세대로 본다. 지금 세대의 401(로그인·체험·로그아웃·내 정보 경로 제외)만 '로그인이 끝남' → `/login?reason=expired`.
  - 세대를 올리면 기대 작업 공간 토큰도 비운다(지난 세션의 목록이 새 세션의 토큰을 정하지 않게). 같은 사람의 세션 교체(비밀번호 변경, 실패 포함)는 토큰을 유지한다 — 409 보호가 꺼지지 않게.

### 6. 작업 공간과 지도 전환 (`ripple/api/workspace.py`, `ripple/store/snapshots.py`)

엑셀로 만든 지도를 확인한 뒤 그 지도로 바꿔 분석한다. 지도가 바뀌어도 이전 지도의 결과·대화·진행 중 응답이 섞이지 않게 하는 규칙이다.

- **지도 저장소**(설정 `RIPPLE_DATA_DIR`, 기본 `.data/` — 깃 제외, 실데이터가 들어감)
  - 지도 `snapshots/<지도 ID>.json` · 정보 `<지도 ID>.info.json`(이름·호선·자료 기준일·가져오기 요약) · 활성 기록 `active.json`(`{"snapshot_id": "G-…"}`, 기본 지도 = 설정의 지도 파일이면 `{"snapshot_id": null}` — 파일에 `null`만 적으면 형식이 맞지 않아 기본 지도로 시작하고 지도 목록·알림 줄에 그 이유와 맞는 형식을 알린다).
  - 쓰기는 임시 파일 → 디스크에 내림 → 바꿔 끼우기, 읽을 때 내용 해시 대조, 경로에 쓰는 ID는 지도 ID 형식부터 확인한다.
- **실시간 시연 세계**(설정 `RIPPLE_SYNTHETIC_CLOCK=live`, 배포 이미지 기본 — 검사·로컬 기본은 `fixed`)
  - 합성 모드의 기본 지도를 지도 파일 대신 생성기 기본 설정으로 **한국 시간 오늘을 기준일로** 만든다(`ripple/api/live_world.py`). 생성기는 모든 날짜를 기준일 + 며칠로 만들어서 날짜만 옮겨진 같은 세계다(같은 시드·같은 설계변경·같은 시연 사례 — 검사 `live_world`).
  - 날이 바뀌면 다음 요청에서 새 날의 세계로 바꾼다. 기본 지도와 그 지도에서 상태만 바꾼 지도(현장 확인·상태 올리기)를 쓰던 세대는 새 날의 기본 지도로 새 세대가 되고(화면은 토큰이 바뀌어 다시 읽음 — 전날 세계의 갱신 지도는 날짜가 그날에 묶이고 새 날의 샘플도 없다), 가져온 지도와 거기서 이어진 갱신 지도를 쓰던 세대는 그대로 둔다.
  - 서버를 다시 켤 때도 같다: 활성 기록이 다른 날 세계에서 상태만 바꾼 지도면 오늘의 기본 지도로 시작하고 지도 목록에 그 이유(`restore_problem`)를 보인다. 그 지도는 목록에 남아 다시 켤 수 있다.
  - 업무상 오늘은 모든 지도가 한국 시간 오늘이다(`docs/domain.md` 12절).
  - **시연 합성 지도**(설정 `RIPPLE_SYNTHETIC_MAP=demo`, 기본 `base` — 공개 시연 배포는 2026-11-04부터 `demo`): 기본 지도 자리에 생성기 설정
    `generator/demo_map.yaml`(기본 설정 + 블록 사이 탑재 순서, `docs/data.md`(생성기) 12절)로 만든 '시연 합성 지도'를 깐다.
    실시간 세계·시연 기록 시드(7절)·합성 과거 사례가 같은 설정으로 세계를 다시 만들어 그대로 돈다. 날짜에 멈춘 세계(`fixed`)면
    지도 파일 기본값이 `data/synthetic_demo/20261020/snapshot.json`(`scripts/generate.py --map demo`). 지도 목록 이름은
    '시연 합성 지도', 기본 자리 표시·샘플·시연 단추는 기본 지도와 같다. 시연 영상 녹화와 공개 시연 배포(Railway api 변수)에 쓴다.
    소개 화면 그림·숫자도 이 지도로 만든다(`scripts/export_showcase.py`, 2026-11-04) — 업무 화면과 같은 ECN-D-0119 출구 9일.
    지도를 바꾸면 시연 기록 시드 판이 바뀌어 다음 시작 때 시연 기록을 자동으로 새로 채운다(7절 — `RIPPLE_RESET_RECORDS` 불필요).
  - 전날 세계에서 남긴 기록은 지도 ID가 달라 '다른 지도 기록'으로 보이고, 결재 규칙(`docs/records.md`(기록·결재) 1절)대로 반려·보류는 되지만 검토 요청·승인은 새 날의 지도로 다시 기록한 개정만 받는다. 전날 기본 지도에 넣은 상태 갱신은 새 날의 기본 지도에 이어지지 않는다(갱신 지도는 목록에 남는다).
- **작업 공간 세대**: 지도·색인·샘플·AI 비서(대화 저장소)·외부 모델 경계를 한 번에 새로 만든 뒤 바꿔 끼운다.
  - 만들다 실패하면 이전 세대·활성 기록 그대로다(활성 기록은 그래프 저장소에 넣은 뒤에 쓴다). 샘플은 기본 지도에만 있다.
- **유효 데이터 모드** = 설정이나 지도가 real이면 real. 올린 엑셀로 만든 지도는 항상 real이라 그 세대의 비서는 외부 모델을 부르지 않는다(문장 해석·설명은 서버 규칙으로만). 상태 확인(`Health.data_mode`)도 유효 모드를 보인다.
- **작업 공간 토큰** = 지도 ID + 서버 프로세스 인스턴스 + 세대. 같은 지도를 다시 켜거나 다른 지도를 갔다 오거나 서버를 다시 켜도 바뀐다.
  - 요청 머리글 `X-Ripple-Workspace`에 화면이 아는 토큰을 싣고, 서버는 다르면 409(`WorkspaceConflict`, 상태는 그대로)로 거절한다. 머리글이 없으면 대조하지 않는다.
  - 요청은 시작할 때 세대를 한 번 잡고 끝까지 그 세대로 계산하며, 응답 머리글에 처리한 세대의 토큰을 단다.
- **요청 종류**(`web/src/api/client.ts`)
  - 묶인 요청(분석·영향·비서·대화·샘플)은 토큰을 싣고, 응답 토큰·기다리는 사이 바뀐 기대값을 대조해 다르면 쓰지 않는다.
  - 동기화(지도 목록·상태)는 토큰을 싣지 않고, 전환(활성화·확정)은 싣는다.
  - 기대 토큰은 목록·전환 응답만 바꾸며, 같은 서버 인스턴스에서 세대가 낮은 목록(늦은 응답)과 지난 인스턴스의 목록은 적용하지 않는다(`web/src/lib/workspace.ts`).
- **화면**: 작업 공간마다 따로인 상태(분석 세션·비서·분석 기준)는 `Workbench`가 갖고, App이 토큰을 key로 그려 지도가 바뀌면 통째로 새로 만든다. 위 막대 지도 메뉴(목록·전환·엑셀 가져오기·내려받기), 가져오기 대화상자, 알림 줄(전환·다른 곳에서 바뀜·복구 실패).
- **분석 기준**(설계변경 목록이 없는 지도): 비서가 새 요청에 쓰는 호선·기준일의 단일 출처.
  - 기준일 기본값은 **자료 기준일**(지도 안의 마지막 상태 날짜: 발주 관측일·단계 진입일·공정 실적 착수·완료일, 없으면 오늘 KST)이고, 자료 기준일과 다르면 계산이 어떻게 달라지는지 한 줄로 알린다.
- **시작 복구**: 활성 기록이 가리키는 지도를 연다. 기록이 깨졌거나 없는 지도를 가리키거나 지도가 손상됐으면 기본 지도로 시작하고, 그 사유를 목록(`restore_problem`)과 화면 알림으로 보인다. 기록은 지우지 않는다.
- **가져오기**: API 흐름은 `docs/input.md`(엑셀 양식) 4절, 파싱 상한(압축 해제 100MB·항목 1,000·시트 64·시트당 행 100,000·칸 2,000,000)은 2절.
  - 엑셀 읽기·제안·확정 매핑 읽기는 한 번에 하나만 한다(읽는 중이면 기다리라고 안내).
  - 확정을 기다리는 가져오기는 30분 · 최근 5개까지 기억한다(`ripple/api/pending_imports.py` `PENDING_TTL_S`·`MAX_PENDING` — 상태 올리기도 같은 규칙).
  - 확정을 마친 가져오기도 30분 · 최근 20개까지 기억해, 확정 응답을 잃은 재시도에 같은 결과를 준다(30분이 지나면 404). 상태 올리기(`ripple/api/status_imports.py`)도 같은 규칙이다.
  - 확정은 둘 다 찾기 → 지도에 적용 → 기억하기를 잠금 하나 안에서 한다(`PendingImports.confirm`): 같은 확정이 동시에 와도 적용·갱신 기록은 한 번이고, 적용 중에 끼어든 열 확인·다시 읽기는 확정이 끝난 뒤 404(받아 놓고 버리지 않음). 상태 올리기의 잠금 순서는 상태 올리기 잠금 → 작업 공간 전환 잠금이다.
- 검사: `tests/checks/workspace.py`(저장소·시작 복구·세대 전환·유효 모드·토큰 409·처리 중 전환·가져오기 상한·재시작).

### 7. 합성 시연 기록 시드 (`ripple/api/demo_seed.py`, 언제 `demo_daily.py`, 각본 `demo_plan.py`)

시연에서 팀장 화면(결재·현황의 결재함·현황·성과·관리)이 비어 보이지 않게, 운영 중인 서비스처럼 지난 기록을 채운다. 설정 `RIPPLE_DEMO_SEED`(on/off, 기본 off).

- **무엇을**: 설계변경 17건에 지난 24일 동안의 기록·검토 요청·결재선 단계 승인·반려·보류·무비용 담당자 처리·실행 시작·종료(감사 줄 80줄)와 실적 6건.
  - 설계변경은 화면 샘플(개발 분할 18건)에서 시연용 네 건(위 막대 시연 ECN-D-0043·0119, 팀 데모 ECN-D-0045, 외자재 운송 시연 ECN-D-0130)을 뺀 14건 + 샘플 밖 세 건. 샘플 가운데 더 저렴한 충족 대안이 있는 건은 0119뿐이라 결재함 '더 저렴한 대안'이 보이게 같은 개발 분할에서 0067을, 무비용(비용이 도면 개정뿐) 건은 샘플에 없어 0015(담당자 처리 뒤 실행)·0007(기록만 — 현장 시연에서 '담당자 처리')을 넣는다(업무 화면에서는 목록 아래 '기록된 다른 설계변경').
  - 결재선(`docs/records.md`(기록·결재) 14절)이 섞이게: 지금 파트장 대기 1(0016) · 파트장 승인 뒤 팀장 대기 3(0067·0131, 팀장 보류 0021) · 팀장 승인 뒤 본부장 대기 1(0106). 지난 건에는 본부장 단계 팀장 전결 2건(0009·0038)과 파트장 반려 1건(0173).
  - 지금 상태: 검토 4 · 보류 1 · 분석 2 · 승인 1 · 실행 4 · 종료 4 · 반려 1.
  - 사람: 담당자 김설계(빠른 로그인 `quick-member`와 같은 사람) · 가상 담당자 이서준(`seed-seojun`) · 정다은(`seed-daeun`), 팀장 박팀장(`quick-lead`), 결재선 가상 계정 이파트장(`part-lead`, 파트장) · 최본부장(`executive`, 본부장) — 김설계·이파트장·박팀장·최본부장은 빠른 로그인 고정 계정과 같은 사람(화면 단추는 김설계·이파트장 둘).
- **어떻게**: 업무 경로와 같은 함수로 한다 — 그날의 시연 세계로 다시 계산해 대조한 기록(`ripple/api/records.py` `record_body`) → 저장소 한 트랜잭션(`commit_record`·`commit_action`, 결재 규칙·감사 사슬 그대로) → 실적(`outcome_entry`). 다른 것은 시각뿐이다(기록 저장소의 시계 주입, 실적 줄의 입력 시각).
  - 금액·결정 기한·처리 시간은 엔진 계산이고, 실적은 그 개정을 계산한 세계의 숨긴 모델(`HiddenModel.outcome`, 생성기 시드 고정) 값이다. 사유·메모·변경 원인·설계 승인 상태처럼 사람이 적는 값만 각본에 있다.
  - AI 호출 기록·AI 제안 수정 기록 같은 시스템 기록은 만들지 않는다(관리 탭에서는 구성원과 감사 로그 확인만 채워진다).
  - 실시간 시연 세계(6절)는 날마다 지도가 바뀌어 검토 요청·승인은 기록한 날에만 받으므로, 각본도 기록 → 검토 요청 → 결정 → 실행 시작을 같은 날에 둔다. 오늘 행동은 오늘 08:30(그 전이면 자정)부터 지금 조금 전 사이에 놓는다 — 결재함의 오늘 건은 그날 바로 승인·반려·보류할 수 있다.
- **언제 — 실시간 시연 세계(`RIPPLE_SYNTHETIC_CLOCK=live`, 배포 기본)는 KST 날마다 자동으로 새로 채운다** (`ripple/api/demo_daily.py`).
  - 데이터 폴더에 표시 `demo_seed.json`(채운 날(KST) · 시드 판)을 남긴다. **시드 판** = 앱·엔진·계약 판 + 백엔드 코드(`ripple/**.py`)·규칙표·파라미터·생성기 설정 내용의 해시 — 문구·계산이 바뀐 배포를 알아본다.
  - 서버가 시작할 때(요청을 받기 전)와 **KST 날이 바뀌어 작업 공간이 새 날의 기본 지도로 넘어갈 때**(6절, 그날 첫 요청), 표시가 오늘·지금 판과 다르거나(없거나 깨짐 포함) 기록이 비어 있으면 그날 기준으로 새로 채운다. 같은 날·같은 판이면 그대로다(다시 시작해도). 백엔드 코드가 바뀐 배포는 같은 날이어도 다시 채우므로 그날 화면에서 남긴 시험 기록도 함께 보관 폴더로 간다.
  - 새로 채우기 = 준비 폴더(`.seed-staging`)의 새 저장소에 각본대로 채운 뒤(약 5초, 지금 기록은 그대로) 기록·실적·수정 기록 파일을 바꿔 끼운다(`ripple/store/reset.py` `swap_records`). 바꿔 끼우는 동안은 데이터 폴더 문(`ripple/store/gate.py`)을 혼자 잡아 다른 연결이 열리지 않는다 — 한 트랜잭션은 옛 기록만 보거나 새 기록만 본다. 새 날 넘어가기는 작업 공간 전환 잠금 안이라 그 사이 요청은 다 채운 뒤의 새 세대를 본다(그날 첫 요청이 몇 초 기다린다).
  - 옛 기록·실적·수정 기록은 지우지 않고 **자동 보관 폴더** `archive/records-auto-<KST 시각>/`(`DONE`에 `auto`·채운 날·판·이유)로 옮긴다. 자동 보관은 **최근 14개만** 남기고 오래된 것은 지운다(사람이 `RIPPLE_RESET_RECORDS` 표지로 만든 보관은 그대로). 시작할 때 기록이 비어 있었으면 보관하지 않는다.
  - 로그: '시연 기록 채움(RIPPLE_DEMO_SEED=on · 날 바뀜 2026-11-08 → 2026-11-09 · 2026-11-09 기준): 설계변경 17건 · 감사 줄 80줄 · 실적 6건 · 가상 담당자 0명 · 옛 기록 보관 archive/records-auto-…'. 이유는 '기록 없음'·'채운 날 표시 없음'·'날 바뀜'·'시드 판 바뀜'.
  - 채우거나 바꿔 끼우다 실패하면 지금 기록을 그대로 두고(바꿔 끼우다 멈추면 옮긴 파일을 되돌림) 이유를 로그에 남긴다. 서버는 계속 돌고 다음 날·다음 시작에 다시 시도한다.
  - 그래서 결재함 D-n은 늘 오늘 기준이고, 오늘 검토 요청한 건은 오늘 지도에 기록돼 결재선(파트장 → 팀장 → 본부장) 승인이 `map_changed`(409) 없이 된다. 그날 화면에서 이어 간 결재는 그날 자정(KST)까지다 — 다음 날 첫 요청에 새로 채운다.
  - **날짜에 멈춘 세계(`fixed`)는 지금처럼** 기록·실적 저장소가 비어 있을 때 시작하면서 한 번만 채운다(로그 '기록이 이미 있어 안 채움', 표시 파일 없음).
  - 지금 지도가 기본 합성 지도가 아니면(가져온 지도·상태만 바꾼 지도) 채우지 않고 경고만 남긴다. 실시간 세계에서 가져온 지도를 쓰던 세대는 날이 바뀌어도 넘어가지 않으므로 새로 채우지 않는다.
  - 가상 계정(빠른 로그인 고정 계정·가상 담당자)은 그대로다(새로 채우기는 기록·실적·수정 기록 파일만 바꾼다).
- **실데이터 금지**: 실데이터 모드(`RIPPLE_DATA_MODE=real`)이거나 지금 지도가 실데이터면 켜져 있어도 아무것도 하지 않고 경고를 남긴다. 사내 설치판에서는 켜지 않는다.
- **가상 담당자 계정**: 계정 파일에 비밀번호를 쓸 수 없는 계정(해시 형식이 아닌 값)으로 넣어 구성원 관리에 보인다. 아이디·비밀번호로는 들어갈 수 없고, 팀장이 구성원 관리에서 임시 비밀번호를 발급하면 쓸 수 있다.
- **결재선 가상 계정**(이파트장 `part-lead` · 최본부장 `executive`): 빠른 로그인 고정 계정(2절)과 같은 아이디라 파트장은 로그인 화면의 '파트장으로 들어가기'로 들어간다(본부장은 화면 단추 없이 결재선 진행 표시로만 — API로는 들어갈 수 있음) — 첫 화면은 결재·현황의 자기 단계 결재함(시드 직후 파트장 0016, 본부장 0106). 비밀번호는 없다(아이디·비밀번호 로그인은 늘 거절).
  - 시드가 켜져 있으면 **시작할 때마다** 계정을 맞춘다(기록이 이미 있어도): 이름·역할·사용 중을 각본 값으로 되돌리고, 비밀번호 해시는 어떤 비밀번호로도 맞지 않는 값으로 둔다. 예전 판이 `RIPPLE_DEMO_PASSWORD`로 만든 해시가 남아 있으면(라이브) 지우고 세션 판을 한 번 올린다 — 그 비밀번호로 만든 세션은 무효이고, 그 뒤 빠른 로그인은 그대로 된다(같은 계정·이름·역할, `tests/checks/demo_seed.py`가 예전 계정이 남은 폴더로 시작해 본다).
  - **`RIPPLE_DEMO_PASSWORD`는 더는 읽지 않는다**(남아 있으면 시작할 때 '삭제 가능' 경고). 빠른 로그인을 끈 배포에서는 이 두 계정으로 들어갈 수 없다(팀장이 전결로 결재선 끝까지).
  - 팀장 계정(API 빠른 로그인 `admin` 또는 아이디 로그인)으로는 전결로 결재선 끝까지 결정할 수 있다(파트장·본부장 계정 없이 — 화면 시연은 담당자·파트장까지). 팀장 혼자 세 단계를 모두 결정할 수 있는 것은 시연 설계다 — 사내 설치판에서는 전결 범위(누가 어느 단계를, 부재 확인·전결 규정)를 회사 규정에 맞춰 좁히는 것이 과제다.
  - 계정 파일이 비어 있지 않으면 첫 관리자 변수(`RIPPLE_ADMIN_*`, 2절)는 관리자를 만들지 않는다. 시작 순서상 첫 관리자가 시드보다 먼저라, 첫 관리자는 시드를 처음 켜는 시작 전이나 같은 시작에 만든다.
- **지우는 법**: 시연 운영에는 더 필요 없다(위 날마다 새로 채우기). 손으로 비우려면 지금처럼 `RIPPLE_RESET_RECORDS`에 새 표지를 넣고 다시 시작한다 — 기록·실적이 보관 폴더로 옮겨지고(배포 4절), 시드가 켜져 있으면 기록이 비었으므로 같은 시작에서 그날 기준으로 다시 채운다. 다시 채우지 않으려면 `RIPPLE_DEMO_SEED`를 지우거나 off로 한 뒤 비운다. 가상 담당자 계정은 비우기로 지워지지 않는다(구성원 관리에서 사용 중지).
- 검사: `tests/checks/demo_daily.py`(새 날 훅 → 자동 보관·다시 채움 · D-n이 새 날 기준 · 채우기 전 전날 기록은 파트장 승인 409, 채운 뒤 409 없음 · 채우는 동안 읽는 스레드는 온전한 수만 · 같은 날 그대로 · 판이 다르면·표시가 깨지면 다시 채움 · 시드 끔·기본 지도 아님·실데이터·fixed는 안 함 · 자동 보관 14개, 사람 보관은 그대로), `tests/checks/demo_seed.py`(꺼짐·실데이터·같은 날 다시 시작 그대로 · 다음 날 시작 자동 보관·다시 채움 · 감사 사슬 · 결재 규칙(그 단계의 결재자 또는 팀장 전결·요청자 ≠ 결정자·무비용 담당자 처리) · 결재선 섞임 · 결재선 가상 계정 비밀번호(없으면 401·변수로 맞추면 그 역할·규칙 위반 값이면 401·파일에 원문 없음) · 시연용 설계변경 제외 · 개정마다 그날 세계로 다시 분석 = 본문 · 실적 = 숨긴 모델 값 · 결재·현황 API · 날이 바뀌면 D-n이 하루 줄어듦 · 날짜에 멈춘 세계).

## 배포

```mermaid
flowchart LR
  U[브라우저] -->|https| W["화면 서비스<br/>Caddy + 정적 화면"]
  W -->|"/api (사설망)"| A["API 서비스<br/>FastAPI · 데이터 볼륨"]
```

- **두 서비스**: 화면 서비스가 `/api`를 사설망의 API 서비스로 넘긴다. 화면과 API가 같은 주소라 쿠키 로그인에 CORS가 필요 없다.
- **라이브는 합성 데이터만** 둔다. 지식 그래프는 메모리에서 계산하고, Neo4j는 사내 설치본에만 둔다.
- **사내 설치**: 같은 Docker 이미지를 `docker compose`로 띄운다(화면·API·Neo4j). 실데이터는 회사 밖으로 나가지 않는다.
- **비밀값**은 배포 플랫폼의 변수와 깃 제외 `.env`에만 둔다. 저장소·문서·로그에는 적지 않는다.
- **이미지 검사**: CI가 매번 이미지를 빌드해 컨테이너 스모크(`scripts/smoke_compose.py` — 화면 캐시·보안 머리글, 로그인·권한, 볼륨 소유권, 기록·승인, 다시 만들기 뒤 세션 유지)를 돌린다.
